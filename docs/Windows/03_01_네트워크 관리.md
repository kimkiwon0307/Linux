# Windows OS 3장 1교시 — 네트워크 관리

## 1. 핵심 개념

| 개념 | 설명 |
|---|---|
| IP | 네트워크에서 장치를 식별하는 주소 |
| Subnet Mask | 네트워크와 호스트 영역 구분 |
| Gateway | 다른 네트워크로 나가는 기본 경로 |
| DNS | 도메인 이름을 IP 주소로 조회 |
| Firewall | 네트워크 통신 허용·차단 |
| RDP | 원격 데스크톱 접속 (TCP 3389) |
| WinRM | Windows 원격 명령 관리 (TCP 5985/5986) |
| SMB | 네트워크 파일 공유 (TCP 445) |

---

## 2. IP·DNS·라우팅 확인

### CMD

```cmd
hostname
ipconfig /all
route print -4
nslookup www.microsoft.com
```

| 명령어 | 역할 |
|---|---|
| hostname | 컴퓨터 이름 확인 |
| ipconfig /all | IP·Subnet·Gateway·DNS 확인 |
| route print -4 | IPv4 라우팅 테이블 확인 |
| nslookup | DNS 조회 |

### PowerShell

```powershell
# IP·Gateway·DNS 확인
Get-NetIPConfiguration

# 네트워크 프로필 확인
Get-NetConnectionProfile

# IPv4 주소 확인
Get-NetIPAddress -AddressFamily IPv4

# IPv4 라우팅 테이블 확인
Get-NetRoute -AddressFamily IPv4
```

## 3. 네트워크 통신·포트 진단

```powershell
# ICMP 응답 확인
ping 192.168.111.155

# 네트워크 경로 확인
tracert -d 192.168.111.155

# RDP TCP 3389 연결 확인
Test-NetConnection 192.168.111.155 -Port 3389

# SMB TCP 445 연결 확인
Test-NetConnection 192.168.111.155 -Port 445
```

| 명령어 | 역할 |
|---|---|
| ping | ICMP 응답 확인 |
| tracert | 목적지까지의 경로 확인 |
| Test-NetConnection | 특정 TCP 포트 연결 확인 |

**중요:** ping 실패가 반드시 서버 접속 불가능을 의미하지는 않는다. ICMP가 차단되어도 TCP 연결은 가능할 수 있다.

## 4. Windows Firewall 관리

### GUI

```text
wf.msc
```

### PowerShell

```powershell
# 방화벽 프로필 확인
Get-NetFirewallProfile

# 현재 네트워크 프로필 확인
Get-NetConnectionProfile

# 방화벽 규칙 확인
Get-NetFirewallRule

# RDP 관련 인바운드 규칙 확인
Get-NetFirewallRule |
    Where-Object {
        $_.Name -like 'RemoteDesktop*' -and
        $_.Direction -eq 'Inbound'
    }
```

- **Inbound:** 외부 → 내 Windows
- **Outbound:** 내 Windows → 외부
- **Profile:** Domain / Private / Public

※ 실습 중 방화벽 전체 비활성화 금지

## 5. RDP 원격 접속 관리

**기본 포트: TCP 3389**

```powershell
# RDP 서비스 상태
Get-Service -Name TermService

# TCP 3389 리스닝 상태 확인
Get-NetTCPConnection -LocalPort 3389 -State Listen

# RDP 접속 가능 여부 확인 (접속하는 PC에서 실행)
Test-NetConnection 192.168.111.155 -Port 3389

# Remote Desktop Users 그룹 구성원 확인
$rdpGroup = Get-LocalGroup -SID 'S-1-5-32-555'
Get-LocalGroupMember -Group $rdpGroup
```

**RDP 장애 확인 순서**

1. IP·라우팅 확인
2. TCP 3389 연결 확인
3. TermService 상태 확인
4. 방화벽 규칙 확인
5. 사용자 인증·원격 로그인 권한 확인

## 6. WinRM 원격 관리

**기본 포트: HTTP 5985 / HTTPS 5986**

```powershell
# WinRM 서비스 확인
Get-Service -Name WinRM

# WinRM 리스너 확인
winrm enumerate winrm/config/listener

# WinRM TCP 포트 리스닝 확인
Get-NetTCPConnection -State Listen |
    Where-Object { $_.LocalPort -in 5985, 5986 }
```

- RDP: 원격 화면 접속
- WinRM: 원격 명령 실행·자동화
- 서비스 실행 상태와 원격 접속 가능 여부는 별개

## 7. SMB 파일 공유

**기본 포트: TCP 445**

공유 폴더 예시:

```text
로컬 경로: C:\SMB-Lab
공유 이름: WinLabShare
UNC 경로: \\192.168.111.155\WinLabShare
```

```powershell
# SMB 서버 서비스 확인
Get-Service -Name LanmanServer

# 공유 목록 확인
Get-SmbShare

# 특정 공유 확인
Get-SmbShare -Name WinLabShare

# 공유 권한 확인
Get-SmbShareAccess -Name WinLabShare

# TCP 445 연결 확인 (접속하는 PC에서 실행)
Test-NetConnection 192.168.111.155 -Port 445
```

### Share Permission vs NTFS Permission

| 구분 | 역할 |
|---|---|
| Share Permission | 네트워크 공유 접근 권한 |
| NTFS Permission | 파일·폴더 자체의 접근 권한 |

네트워크 공유 접근 시 두 권한을 모두 만족해야 한다.

예시:
- Share: Change
- NTFS: Read
- 결과: 파일 읽기 가능, 수정 불가

## 8. 실무 장애 대응

| 증상 | 확인 항목 |
|---|---|
| IP 통신 장애 | ipconfig, Get-NetRoute |
| DNS 조회 실패 | nslookup, DNS 설정 |
| TCP 포트 접속 실패 | Test-NetConnection, 방화벽·서비스 |
| RDP 로그인 실패 | 계정·암호·RDP 권한 |
| SMB 접근 불가 | TCP 445, 공유 이름, 인증 |
| SMB 파일 수정 불가 | Share Permission, NTFS Permission |
| 관리자 권한 오류(0x5) | 실행 계정·UAC·관리자 권한 |

### 장애 대응 기본 흐름

1. IP·Subnet·Gateway·DNS 확인
2. ping·tracert로 기본 통신 및 경로 확인
3. Test-NetConnection으로 서비스 포트 확인
4. Get-Service로 서비스 상태 확인
5. Firewall 및 사용자·파일 권한 확인
6. 원인 조치 후 정상 동작 재검증

## 9. 필수 암기 명령어 TOP 7

| 명령어 | 암기 내용 |
|---|---|
| `ipconfig /all` | IP 설정 확인 |
| `ping` | ICMP 응답 확인 |
| `tracert` | 네트워크 경로 확인 |
| `Test-NetConnection` | TCP 포트 연결 확인 |
| `Get-NetFirewallRule` | 방화벽 규칙 확인 |
| `Get-Service` | 서비스 상태 확인 |

**핵심:** IP → 통신 → 포트 → 서비스 → 방화벽 → 권한 순서로 장애 원인을 좁혀간다.
