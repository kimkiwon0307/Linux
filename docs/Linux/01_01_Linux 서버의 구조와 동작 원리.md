## 1. 운영체제(OS)란?

운영체제(OS)는 컴퓨터의 하드웨어 자원을 관리하고 프로그램이 실행될 수 있는 환경을 제공하는 소프트웨어이다.

### 운영체제의 역할
- CPU 및 프로세스 관리
- 메모리 관리
- 디스크 및 파일시스템 관리
- 네트워크 관리
- 프로그램 실행 환경 제공

**핵심:** 운영체제는 프로그램이 하드웨어를 안전하고 효율적으로 사용할 수 있도록 관리한다.

---

## 2. Linux와 Ubuntu의 차이

| 구분 | 설명 |
|---|---|
| Linux | 운영체제의 핵심인 커널(Kernel) |
| Ubuntu | Linux 커널과 여러 프로그램을 묶은 배포판 |
| Debian | Linux 배포판의 한 종류 |
| Rocky Linux | 기업 서버에서도 사용하는 Linux 배포판 |

### Ubuntu를 사용하는 이유
- 무료로 사용할 수 있다.
- 서버 관련 공식 문서와 자료가 풍부하다.
- `apt`로 프로그램을 설치하고 관리할 수 있다.
- AWS, Docker, Kubernetes 학습과 연계하기 좋다.
- LTS 버전은 장기 유지보수를 제공한다.

**핵심:** Linux는 엄밀하게는 커널이고, Ubuntu는 Linux 커널을 포함하는 완성된 운영체제 배포판이다.

---

## 3. Kernel(커널)이란?

Kernel은 운영체제의 핵심으로, 하드웨어 자원과 프로세스를 관리한다.

### Linux 동작 구조

```text
         사용자
            ↓
    Shell / 응용 프로그램
            ↓
       Linux Kernel
            ↓
    CPU / RAM / Disk / NIC
```

### 커널의 주요 역할

| 역할 | 설명 | 실무 사례 |
|---|---|---|
| 프로세스 관리 | 프로그램 실행과 CPU 사용 시간 관리 | Nginx 프로세스 관리 |
| 메모리 관리 | 메모리 할당 및 회수 | 메모리 부족 분석 |
| 파일시스템 관리 | 파일 읽기·쓰기 처리 | 로그 파일 관리 |
| 네트워크 관리 | 네트워크 패킷 처리 | 서버 통신 장애 분석 |
| 장치 관리 | 하드웨어 장치 관리 | 디스크 인식 오류 확인 |

### 실제 사례

Nginx 웹 서버를 실행하면 다음 과정이 발생한다.

1. 관리자가 Nginx 서비스 시작을 요청한다.
2. systemd가 Nginx 프로세스를 실행한다.
3. Linux 커널이 CPU와 메모리 등 자원을 관리한다.
4. Nginx가 네트워크를 통해 HTTP 요청을 처리한다.

**핵심:** 커널은 프로그램이 하드웨어 자원을 사용할 수 있도록 관리하는 운영체제의 핵심이다.

## 4. Shell과 Terminal

| 용어 | 설명 |
|---|---|
| Terminal | 명령어를 입력하고 결과를 확인하는 인터페이스 |
| Shell | 사용자의 명령을 해석하고 실행하는 프로그램 |
| Bash | Linux에서 널리 사용하는 Shell |
| CLI | 문자 기반 명령어 조작 방식 |
| GUI | 마우스와 그래픽 기반 조작 방식 |

### 명령어 실행 흐름

```text
사용자 명령어 입력
        ↓
    Bash가 처리
        ↓
  명령어/프로그램 실행
        ↓
 필요시 커널 기능 사용
        ↓
     결과 출력
```

### 서버에서 CLI를 사용하는 이유
- SSH를 통한 원격 관리가 편리하다.
- 반복 작업을 스크립트로 자동화할 수 있다.
- 그래픽 환경이 없어도 서버를 운영할 수 있다.

## 5. Linux 서버란?

Linux 기반 운영체제에서 웹 서비스, 데이터베이스 등의 서비스를 제공하는 컴퓨터이다.

### 웹 서비스 동작 예시

```text
사용자 PC
    |
    | HTTP 요청
    ↓
Linux 서버 (Ubuntu)
    |
    ↓
Nginx 웹 서버
    |
    | HTTP 응답
    ↓
사용자 PC
```

Ubuntu를 설치했다고 자동으로 웹 서버가 되는 것은 아니다.

Nginx 같은 웹 서버 프로그램을 설치하고 실행해야 웹 요청을 처리할 수 있다.

### Linux 엔지니어의 업무
- 서버 설치 및 초기 설정
- 사용자와 권한 관리
- 프로세스 및 서비스 관리
- CPU·메모리·디스크·네트워크 점검
- 서버 보안 설정
- 로그 분석 및 백업
- 장애 원인 분석과 복구

## 6. VMware와 가상머신(VM)

VMware Workstation을 사용하면 실제 컴퓨터 한 대에서 여러 가상 서버를 실행할 수 있다.

### 가상화 구조

```text
실제 컴퓨터 (Host)
Windows + CPU + RAM + SSD
          |
          ↓
   VMware Workstation
          |
    ┌─────┴─────┐
    ↓           ↓
 Linux01      Linux02
 Ubuntu       Ubuntu
 Kernel       Kernel
```

### 주요 용어

| 용어 | 의미 |
|---|---|
| Host | VMware가 실행되는 실제 컴퓨터 |
| Guest OS | VM 내부에서 실행되는 운영체제 |
| VM | 가상의 독립적인 컴퓨터 |
| Hypervisor | 가상머신 실행 및 자원 가상화를 담당 |
| vCPU | 가상머신에 제공되는 가상 CPU |

### VMware를 사용하는 이유

1. 물리 서버를 별도로 구매할 필요가 없다.
2. 한 컴퓨터에서 여러 운영체제를 실행할 수 있다.
3. VM마다 CPU·메모리·디스크를 할당할 수 있다.
4. 스냅샷으로 이전 상태를 복원할 수 있다.
5. 서버 구축 및 장애 대응을 안전하게 실습할 수 있다.

---

## 7. VM과 Docker 컨테이너의 차이

| 구분 | VM | 일반적인 Linux 컨테이너 |
|---|---|---|
| OS | 독립적인 Guest OS | 호스트 커널 기반 실행 환경 |
| 커널 | VM별 독립적인 커널 | 호스트 Linux 커널 공유 |
| 자원 사용 | 상대적으로 무거움 | 상대적으로 가벼움 |
| 주된 용도 | 독립 서버 환경 | 애플리케이션 격리·실행 |

**핵심 암기**
- VM은 독립적인 운영체제와 커널을 실행한다.
- 일반적인 Linux 컨테이너는 호스트 커널을 공유한다.

## 8. Linux 기본 명령어

### 8-1. 운영체제 및 사용자 정보 확인

```bash
whoami                 # 현재 로그인한 사용자
hostname               # 서버 호스트명
cat /etc/os-release    # OS 배포판 정보
uname -r               # 현재 실행 중인 커널 버전
```

### 8-2. 시스템 자원 확인

```bash
nproc                  # 사용 가능한 논리 CPU 개수
free -h                # 메모리 사용량
lsblk                  # 디스크 및 파티션 구조
df -h /                # 루트 파일시스템 사용량
```

### 명령어와 옵션 설명

| 명령어·옵션 | 의미 |
|---|---|
| `whoami` | 현재 사용자 확인 |
| `hostname` | 서버 이름 확인 |
| `cat` | 파일 내용 출력 |
| `uname -r` | 커널 릴리스 정보 출력 |
| `nproc` | 사용 가능한 논리 CPU 수 |
| `free -h` | 메모리를 읽기 쉬운 단위로 출력 |
| `lsblk` | 블록 장치 목록 출력 |
| `df -h /` | 루트 파일시스템의 디스크 사용량 확인 |

## 9. Linux 서버 장애 대응 기초

### 상황: Linux 서버가 갑자기 느려졌다.

서버가 느려졌다고 무조건 재부팅하면 안 된다.

먼저 시스템 자원과 로그를 확인하고 원인을 분석해야 한다.

### 기본 점검 명령어

```bash
top                     # CPU 및 프로세스 상태 확인
free -h                 # 메모리 사용량 확인
df -h                   # 파일시스템 용량 확인
journalctl -p err -b     # 이번 부팅의 오류 우선순위 로그 확인
```

### 장애 대응 순서

```text
1. 장애 증상 확인
        ↓
2. CPU·메모리·디스크 점검
        ↓
3. 프로세스 및 로그 분석
        ↓
4. 장애 원인 파악
        ↓
5. 원인에 맞는 조치
        ↓
6. 정상 복구 검증
```

**핵심:** 장애 대응은 명령어를 무작정 실행하는 것이 아니라, 상태와 로그를 분석하여 원인을 좁혀가는 과정이다.

## 11. 면접 예상 질문

### Q1. Linux 커널이란 무엇인가요?

CPU, 메모리, 프로세스, 파일시스템, 네트워크 등 시스템 자원을 관리하는 운영체제의 핵심입니다.

### Q2. Linux와 Ubuntu의 차이는 무엇인가요?

Linux는 엄밀하게는 커널을 의미하고, Ubuntu는 Linux 커널과 여러 프로그램을 포함한 운영체제 배포판입니다.

### Q3. VMware를 사용하는 이유는 무엇인가요?

한 대의 물리 컴퓨터에서 독립적인 운영체제를 가진 여러 가상 서버를 구축할 수 있고, 스냅샷을 이용하여 장애와 복구를 실습할 수 있기 때문입니다.

### Q4. VM과 컨테이너의 차이는 무엇인가요?

VM은 각각 독립적인 운영체제와 커널을 실행하지만, 일반적인 Linux 컨테이너는 호스트 Linux 커널을 공유합니다.

### Q5. Linux 서버가 느려지면 어떻게 대응하나요?

CPU·메모리·디스크·프로세스 상태를 확인하고 로그를 분석합니다. 이후 원인을 파악하여 조치하고 정상적으로 복구되었는지 검증합니다.
