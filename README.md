# 🐧 Linux 

> **리눅스 명령행 인터페이스(CLI)와 셸(Shell)의 핵심 개념을 정리한 문서입니다.**

---

## 1. 명령행 인터페이스 (CLI) 핵심 정리

### 셸 (Shell)이란?
사용자가 입력한 명령어를 해석하여 **리눅스 커널(Kernel)**에게 전달하고 실행 결과를 사용자에게 보여주는 명령어 프로그램이다.

* **역할:** 사용자 ↔ 커널 사이의 다리(인터페이스) 역할
* **대표적인 셸 종류:**
    * `bash` (Bourne Again Shell): 가장 널리 쓰이는 표준 셸
    * `zsh` (Z Shell): 강력한 플러그인과 테마(Oh My Zsh)를 지원하는 최신 셸
    * `sh` (Bourne Shell): 가장 기본적인 전통 셸
* **기본 셸 확인:** Ubuntu 등 대부분의 주요 리눅스 배포판은 기본 셸로 **`bash`**를 채택하고 있습니다.

## 2. 시작하고 종료하기

### 📂 자주 쓰는 기본 명령어
* `pwd` : 현재 작업 중인 디렉터리 경로 출력
* `ls` : 현재 위치의 파일 및 폴더 목록 보기
* `cd` : 지정한 폴더로 이동

## 3. 시스템 제어 및 가상 콘솔

### 🛑 시스템 종료 및 재부팅
* **시스템 제어:** `poweroff`, `shutdown`, `halt` 명령어를 통해 시스템을 제어할 수 있습니다.
* **재부팅 명령어:** `shutdown -r now`, `reboot`, `init 6` 등을 사용합니다.

### 🖥️ 가상 콘솔의 이해와 활용
리눅스는 여러 개의 독립적인 작업을 수행할 수 있도록 **가상 콘솔** 기능을 제공합니다.
* **단축키 전환:** `Ctrl` + `Alt` + `F2` ~ `F6` 키를 누르면 터미널 모드 화면으로 즉시 전환됩니다.
* **명령어 전환:** `chvt [콘솔번호]` 명령어를 통해서도 원하는 콘솔 번호로 이동이 가능합니다.

### ⚙️ 시스템 관리자를 위한 고급 종료 제어
* **종료 예약:** `shutdown -h +5` 명령은 5분 뒤 시스템을 종료하겠다는 예약을 설정합니다.
* **예약 취소:** `shutdown -c`를 사용하면 이미 예약된 종료 명령을 언제든지 취소할 수 있습니다.
* **경고 메시지 전송:** `shutdown -k` 옵션은 실제로 종료하지 않고 접속된 사용자들에게 경고 메시지만 보낼 때 유용합니다. (시스템 부하를 줄이거나 관리 작업을 유도할 때 활용)

## 4. 리눅스 파일 시스템 및 디렉토리 구조

### 🗂️ 윈도우즈 vs 리눅스 디렉토리 구조 차이
| 운영체제 | 최상위 개념 | 경로 구분자 | 구조 특징 |
| :--- | :--- | :--- | :--- |
| **Windows** | 드라이브 개념 (`C:\`, `D:\`) | 백슬래시 (`\`) | 독립적인 드라이브 중심 |
| **Linux** | 최상위 디렉토리 (`/`) | 슬래시 (`/`) | 모든 디렉토리가 하나로 연결된 계층 구조 |

### 🔍 파일 시스템 탐색 명령어
* **전체 구조 시각화:** `tree` 명령어를 통해 디렉토리 구조를 한눈에 볼 수 있습니다.
* **목록 확인 (`ls`):** 현재 위치한 디렉토리 목록을 확인합니다.
  * `-l` : 파일의 상세 정보(권한, 소유자, 크기 등) 확인
  * `-a` : 숨김 파일까지 포함하여 전체 확인
* **파일 종류 식별 (앞글자 표시):**
  * `d`로 시작하면 **디렉토리(폴더)**
  * 하이픈(`-`)으로 시작하면 **일반 파일**

### 📍 디렉토리 이동과 현재 위치 확인
* `pwd` : 현재 작업 중인 디렉토리의 절대 경로를 출력합니다.
* `cd` : 디렉토리를 변경(이동)합니다.
  * `.` : 현재 디렉토리 의미
  * `..` : 상위 디렉토리 의미
  * `cd` (경로 없음) : 사용자의 **홈 디렉토리**로 즉시 이동

### 📝 파일 및 디렉토리 생성과 삭제
* **파일 생성:** `touch [파일명]` 명령어를 사용해 빈 파일을 만들 수 있습니다.
* **파일 삭제:** `rm [파일명]` 명령어를 사용해 삭제합니다.
* **디렉토리 관리:** * `mkdir [폴더명]` : 새로운 디렉토리 생성
  * `rmdir [폴더명]` : 디렉토리가 **비어 있을 때만** 삭제 가능
  * ⚠️ `rm -rf [폴더명]` : 내부 파일 및 하위 폴더까지 모두 강제로 삭제하므로 **매우 주의해서 사용**해야 합니다.

### 📋 파일 복사, 이동 및 내용 확인
* **복사 및 이동:** 복사할 때는 `cp`, 이동하거나 이름을 바꿀 때는 `mv` 명령어를 사용합니다.
* **내용 확인 (`cat`):** 파일의 전체 내용을 터미널에 출력합니다.
* **부분 확인 (`head`):** 파일의 맨 위 내용만 확인합니다.
  * 기본적으로 맨 위 10줄을 보여주며, `head -n 10` (또는 `head +10`) 형태로 옵션을 활용합니다.
* **페이지 단위 확인:** 파일 내용이 길 때는 파이프(`|`)를 이용해 `more`나 `less` 명령어로 연결하여 화면 단위로 끊어서 보는 것이 편리합니다.
  > 예시: `cat filename.txt | less`

### 🛠️ 파일 종류 식별 및 시스템 관리
* 리눅스는 윈도우즈와 달리 **파일 확장명(.txt, .exe 등)에 의존하지 않습니다.**
* 파일의 실제 성격을 정확히 파악하기 위해서는 `file [파일명]` 명령어를 사용해야 합니다.
* 이를 통해 해당 파일이 텍스트 파일인지, 실행 파일인지, 혹은 블록 장치인지 정확하게 식별할 수 있습니다.

## 5. 리눅스 사용자 및 그룹 관리

### 👥 다중 사용자 시스템의 이해
* 리눅스는 여러 명의 사용자가 동시에 시스템에 접속하여 독립적으로 작업할 수 있는 **다중 사용자 관리 시스템(Multi-User System)**입니다.

### 📄 사용자 정보 관련 주요 파일
사용자의 계정 및 보안 정보는 시스템 내 특정 파일에서 안전하게 관리됩니다.
* **`/etc/passwd` (사용자 기본 정보):** 사용자의 상세 정보가 정의된 파일입니다.
  * 각 행은 `사용자 이름`, `암호(X 표시)`, `사용자 ID(UID)`, `그룹 ID(GID)`, `홈 디렉토리`, `기본 셸 정보` 순으로 구성되어 있습니다.
  * 일반적으로 새로 생성되는 일반 사용자는 **1001번**부터 ID가 순차적으로 할당됩니다.
* **`/etc/shadow` (암호화된 비밀번호):** 계정 비밀번호는 보안을 위해 별도로 분리되어 **암호화된 상태**로 저장됩니다.

### 🛠️ 그룹 관리 및 사용자 생성 메커니즘
* **`/etc/group` (그룹 정보 관리):** 사용자가 소속된 그룹 정보들이 저장되고 관리되는 파일입니다.
* **기본 그룹 자동 생성:** 새로운 사용자를 생성할 때 별도의 그룹을 지정하지 않으면, 시스템은 **사용자 이름과 동일한 이름의 전용 그룹**을 자동으로 생성합니다.
* **특정 그룹 지정 생성:** `useradd` 또는 `adduser` 명령어 사용 시 `--gid` 옵션을 활용하면 생성과 동시에 특정 그룹에 사용자를 바로 배치할 수 있습니다.
* **기본 환경 설정 (`/etc/skel`):** 새 사용자가 생성되면 해당 사용자의 홈 디렉토리에 셸 환경 설정 파일들이 자동으로 복사됩니다. 이 파일들은 `/etc/skel` 폴더에 있는 기본 템플릿 파일들을 기반으로 합니다.

### 🔍 파일의 속성과 상세 정보 확인
* **상세 속성 조회:** 리눅스 시스템에서 파일의 상세 정보를 확인하려면 `ls -l` 명령어를 사용해야 합니다.
* **표시 정보 종류:** 파일의 유형, 허가권(권한), 링크 수, 소유자 및 소유 그룹, 파일 크기, 마지막 수정 날짜 등이 표시됩니다.
* **파일 유형 식별 (앞글자 표시):**
  * 하이픈(`-`) : **일반 파일**
  * `d` : **디렉토리(폴더)**
  * `l` : **링크 파일(바로가기)**

### 🔐 파일 허가권(Permission)의 이해와 설정
* **권한 구조:** 파일의 허가권은 `소유자(User)`, `소유 그룹(Group)`, `기타 사용자(Others)`라는 세 그룹으로 구분됩니다.
* **권한 종류:** 각 그룹은 읽기(`r`), 쓰기(`w`), 실행(`x`) 권한을 독립적으로 부여받습니다.
* **허가권 변경:** 파일의 권한을 변경할 때는 `chmod [권한] [파일명]` 명령어를 사용합니다.

### 👑 소유권 변경 및 관리자 권한의 중요성
* **소유권 및 그룹 변경:** 파일의 소유자는 `chown`, 소유 그룹은 `chgrp` 명령어를 통해 변경할 수 있습니다.
* **보안 제약:** 시스템 보안상의 이유로 파일의 소유권을 바꾸는 `chown` 명령어는 **오직 루트(Root) 사용자(관리자 권한)**만 실행할 수 있습니다.


## 🔗 6. 리눅스 파일 링크 관리

### 📌 리눅스 파일 링크의 기본 개념
우분투 리눅스에서 파일 링크는 크게 **심볼릭 링크(Symbolic Link)**와 **하드 링크(Hard Link)** 두 가지 방식으로 나뉩니다.
* **심볼릭 링크:** 윈도우의 '바로가기 아이콘'과 유사한 개념으로, 원본 파일의 위치(경로)를 가리키는 포인터 역할을 합니다.
* **하드 링크:** 리눅스만의 고유한 방식으로, 원본 파일이 사용하는 **아이노드(inode)**를 공유하며 원본과 동일한 데이터에 직접 접근하는 특징을 가집니다.

### ⚙️ 심볼릭 링크와 하드 링크의 기술적 차이
* **심볼릭 링크:** 링크를 생성하면 **새로운 아이노드가 할당**되며, 이 아이노드가 원본 파일의 경로를 가리키는 간접적인 연결고리를 형성합니다.
* **하드 링크:** 원본 파일과 **동일한 아이노드 번호를 공유**하기 때문에, 파일 시스템 내부적으로는 동일한 데이터 블록을 직접 참조하게 됩니다.

### 💻 실습을 통한 링크 동작 확인
리눅스에서는 `ln` 명령어를 통해 링크를 생성할 수 있습니다.
* **하드 링크 생성:** 옵션 없이 실행 (`ln [원본파일] [링크파일]`)
* **심볼릭 링크 생성:** `-s` 옵션을 사용 (`ln -s [원본파일] [링크파일]`)

> 🔍 **아이노드 확인 명령어:** > `ls -li` 명령어를 실행해보면, 하드 링크는 원본 파일과 아이노드 번호가 정확히 일치하는 반면, 심볼릭 링크는 별도의 고유한 번호를 가진 것을 확인할 수 있습니다.

### ⚠️ 원본 파일 삭제 시의 영향력
원본 파일이 삭제되었을 때 두 링크의 동작은 완전히 다르게 나타납니다.

* **하드 링크:** 원본 데이터의 아이노드를 직접 참조하고 있기 때문에, 원본 파일이 사라져도 **데이터에 아무런 문제 없이 접근이 가능**합니다.
* **심볼릭 링크:** 원본 파일의 '경로'를 참조하기 때문에, 원본 파일이 제거되면 **링크가 끊겨 파일을 읽을 수 없는 상태(Broken Link)**가 됩니다.

## 📦 7. 데비안 패키지와 dpkg 명령어의 이해

### 📌 데비안 패키지의 기본 개념
우분투 리눅스에서 소프트웨어를 설치하기 위한 핵심 단위는 **데비안 패키지**이며, 확장명이 `.deb`로 끝나는 설치 파일을 사용합니다.
* **패키지 파일명 구조:** 파일 이름은 `패키지이름`, `버전`, `개정 버전`, `CPU 아키텍처 정보`로 규칙성 있게 구성됩니다.

### ⚙️ dpkg 명령어와 주요 옵션
패키지를 관리하기 위해 사용되는 `dpkg` 명령어는 다양한 기능의 옵션을 제공합니다.

* **패키지 설치:** `dpkg -i [패키지명.deb]`
* **패키지 삭제:** `dpkg -r [패키지명]` (설정 파일은 남김)
* **완전 삭제:** `dpkg -P [패키지명]` (설정 파일까지 모두 포함하여 삭제)
* **설치된 패키지 조회:** `dpkg -l [패키지명]`
* **패키지 상세 정보 확인:** `dpkg --info [패키지명.deb]` (설치 전에 확인 가능)

### ⚠️ dpkg 명령어의 한계와 의존성 문제
* `dpkg` 명령어는 로컬 파일을 직접 다루기 때문에 직관적이지만, 프로그램 실행에 필요한 다른 패키지들을 자동으로 함께 설치해주지 못하는 **'의존성 문제(Dependency Problem)'**라는 구조적 한계를 가지고 있습니다.

## 🛠️ 8. APT를 이용한 편리한 패키지 관리

### 📌 APT(Advanced Package Tool)의 기본 개념
`dpkg` 명령어의 기존 의존성 문제를 해결해 주는 핵심 도구가 바로 **APT**입니다.
* **의존성 자동 해결:** APT는 인터넷 저장소를 통해 필요한 패키지는 물론, 해당 패키지를 구동하기 위해 필요한 하위 패키지(의존성 파일)들까지 자동으로 추적하고 다운로드하여 한꺼번에 설치해 주는 강력한 기능을 제공합니다.

### ⚙️ APT 주요 명령어 및 활용
* **패키지 설치:** `sudo apt -y install [패키지이름]` (`-y` 옵션으로 설치 확인 질문에 자동 승인)
* **패키지 삭제:** `sudo apt remove [패키지이름]` (설정 파일 유지)
* **패키지 완전 삭제:** `sudo apt purge [패키지이름]` (설정 파일까지 삭제)
* **미사용 패키지 정리:** `sudo apt autoremove` (의존성 때문에 설치되었으나 현재는 사용되지 않는 패키지 정리)
* **캐시 파일 캐시 삭제:** `sudo apt clean` (다운로드된 설치 파일(`.deb`)들을 제거하여 용량 확보)

### 🌐 패키지 저장소(Repository) 작동 원리
패키지 정보는 시스템 내 `/etc/apt/sources.list.d/ubuntu.sources` 파일에 저장된 주소를 기반으로 관리됩니다.

1. **목록 확보:** `apt install` 명령을 내리면 시스템은 설정 파일에 기록된 인터넷 주소(URL)로 접속하여 패키지 목록을 먼저 확보합니다.
2. **단계적 설치:** 이후 사용자가 설치를 확정하면 실제 패키지 파일을 안전하게 다운로드하고 설치하는 과정을 거칩니다.

> 📊 **우분투 공식 저장소의 4가지 분류**
>
> | 저장소 이름 | 설명 |
> | :--- | :--- |
> | **Main** | 우분투가 공식적으로 지원하는 기본 무료 소프트웨어 |
> | **Universe** | 우분투가 공식 지원하지는 않지만, 커뮤니티에서 관리하는 무료 소프트웨어 |
> | **Restricted** | 우분투가 공식 지원하는 유료 또는 기기용 제한적 소프트웨어(드라이버 등) |
> | **Multiverse** | 우분투가 공식 지원하지 않는 유료 및 저작권 제한 소프트웨어 |
> 
> * 사용자는 필요에 따라 저장소 미러 사이트를 변경하거나 업데이트 관련 설정을 자유롭게 수정하여 조절할 수 있습니다.

### 🚀 고급 설정 및 업데이트 실습
* **저장소 목록 갱신:** `sudo apt update`
  * 저장소 주소를 직접 관리하거나 변경할 때는 반드시 이 명령을 실행하여 변경된 최신 설정을 시스템에 동기화해야 합니다.
* **전체 패키지 업그레이드:** `sudo apt upgrade`
  * 이 명령을 실행하면 현재 시스템 내에 설치된 모든 패키지를 현재 시점의 최신 상태로 일괄 유지할 수 있습니다.

### ⚙️ 프로세스 관리하기
> 💡 **프로세스란?** 현재 시스템에서 실행 중인 프로그램을 말합니다. 서버 장애의 대부분은 프로세스 다운(죽음), CPU 과다 사용, 메모리 부족과 관련이 깊으므로 프로세스 관리는 서버 운영의 핵심입니다.

#### 1) 프로세스 확인하기
* `ps` : 가장 기본적인 현재 프로세스 상태 출력
* `ps -ef` : 시스템에서 실행 중인 모든 프로세스를 상세히 출력
* `ps -ef | grep nginx` : 전체 프로세스 중 특정 프로세스(예: nginx)만 필터링하여 검색
* `top` : 실시간 CPU 및 메모리 사용량과 프로세스 순위 보기
* `htop` : Ubuntu 등에서 많이 사용하는 모니터링 도구로, `top`보다 시각적으로 깔끔하고 직관적임

#### 2) 열린 파일 및 포트 조회하기
* `sudo lsof -i` : 현재 네트워크(포트)를 사용 중인 모든 프로세스 표시
* `sudo lsof -i :80` : 현재 80번 포트(웹 서비스 등)를 어떤 프로세스가 점유하고 있는지 확인

#### 3) 작업 제어하기
리눅스는 명령어를 눈앞에서 실행하는 **포그라운드(Foreground)**와 뒤에서 조용히 실행하는 **백그라운드(Background)** 개념이 있습니다.

* `[명령어] &` : 명령어를 백그라운드에서 실행 (예: `sleep 100 &`을 입력하면 100초 대기 작업을 뒤로 던져 터미널을 계속 사용할 수 있음)
* `jobs` : 현재 백그라운드에서 실행 중인 작업 목록 표시
* `fg` : 백그라운드에서 돌고 있는 작업을 다시 눈앞(Foreground)으로 가져오기

<img width="1202" height="535" alt="image" src="https://github.com/user-attachments/assets/1614bada-03d1-428a-98e3-27b3f28625c6" />

#### 4) 프로세스 상태 변경하기
* `kill [PID]` : 지정한 프로세스 ID(PID)에 종료 신호를 보내 안전하게 종료
* `kill -9 [PID]` : 프로세스를 예외 없이 즉시 강제 종료 (안전한 종료가 안 될 때 최종 수단으로 사용)
* `pkill nginx` : PID를 모를 때, 프로세스의 이름(예: nginx)을 지정하여 일괄 종료

### 📦 패키지 관리하기
> 💡 **패키지란?** 리눅스 프로그램의 설치 파일 묶음입니다. (윈도우의 `.exe` 설치 파일과 유사합니다.)

#### 1) dpkg (데비안 패키지 관리 도구)
Ubuntu는 데비안(Debian) 계열 리눅스이기 때문에 `.deb` 확장자의 패키지 파일을 사용합니다.
* `sudo dpkg -i file.deb` : 다운로드한 패키지 파일 설치
* `dpkg -l` : 시스템에 설치된 전체 패키지 목록 확인
> 🛠️ *참고:* 의존성(함께 설치되어야 하는 파일들)을 스스로 해결하지 못하므로, 실무에서는 주로 아래의 `apt`를 사용합니다.

#### 2) apt (고급 패키지 도구)
인터넷 저장소에서 패키지와 의존성 파일까지 알아서 다운로드해 설치해 주는 Ubuntu의 핵심 패키지 관리자입니다.
* `sudo apt update` : 인터넷 저장소의 최신 패키지 목록(인덱스) 업데이트 (설치 전 필수 실행)
* `sudo apt upgrade` : 현재 설치된 모든 패키지를 최신 버전으로 업그레이드
* `sudo apt install nginx` : 특정 패키지(예: nginx) 설치
* `sudo apt remove nginx` : 설치된 패키지 삭제
* `apt search nginx` : 원하는 패키지가 저장소에 있는지 이름으로 검색

## 🗜️ 9. 리눅스 파일 압축과 아카이브(묶기)

### 📌 파일 압축과 해제 (`xz`, `bzip2`, `gzip`)
리눅스 환경에서는 다양한 압축 형식을 지원하며, 각 확장명에 따라 사용하는 명령어가 달라집니다.
* **압축률 특징:** `xz`와 `bzip2`는 다른 방식에 비해 상대적으로 압축률이 매우 우수합니다.
* **주의사항:** 리눅스에서 단일 파일 압축 명령어를 사용하면 **원본 파일이 사라지고 압축된 파일만 남는 특징**이 있습니다.
* **압축 해제:** 압축을 해제할 때는 일반적으로 각 명령어에 `-d` (Decompress) 옵션을 사용합니다.

### 📦 파일 묶기 (`tar`)
리눅스에서 파일 묶기(아카이브)는 압축과 완전히 별개의 작업으로 간주됩니다. 여러 파일을 하나로 뭉치기 위해서는 `tar` 명령어를 사용합니다.

* **기본 묶기:** `tar cvf [파일명.tar] [대상디렉토리나 파일]` (가장 표준적인 방법)
* **기본 풀기:** `tar xvf [파일명.tar]`

### ⚡ tar와 압축 옵션의 결합
`tar` 명령어는 파일을 묶음과 동시에 압축을 진행할 수 있도록 확장 옵션을 제공합니다. 묶을 때 사용한 확장자를 명시적으로 붙여주는 것이 추후 관리에 용이합니다.

| 압축 형식 | 확장자 | 묶기 + 압축 옵션 | 풀기 + 압축해제 옵션 |
| :--- | :--- | :--- | :--- |
| **xz** | `.tar.xz` | `tar cJvf` | `tar xJvf` |
| **gzip** | `.tar.gz` | `tar czvf` | `tar xzvf` |
| **bzip2** | `.tar.bz2` | `tar cjvf` | `tar xjvf` |

## 🔍 10. 효율적인 파일 검색과 관리

### 📌 `find` 명령어를 이용한 정밀 검색
리눅스에서 특정 파일을 찾을 때는 `find` 명령어가 가장 범용적으로 사용됩니다. 사용자는 특정 디렉터리 경로 내에서 이름, 크기, 시간 등의 조건을 지정하여 정밀하게 파일을 검색할 수 있습니다.

* **이름으로 검색:** `find [경로] -name "[파일명]"`
* **크기로 검색:** `find [경로] -size [크기]`

### ⚙️ `-exec` 옵션을 활용한 연계 작업
`find` 명령어의 `-exec` 옵션을 활용하면 검색된 결과물에 대해 원하는 명령어를 즉시 연달아 실행할 수 있습니다.

* **활용 예시 (일괄 삭제):**
  ```bash
  find . -name "*.log" -exec rm -f {} \;
  ```

## ⏰ 11. Linux 작업 자동화: cron과 at

### 📌 cron과 at의 기본 개념
리눅스에서는 반복되거나 예약된 작업을 자동으로 실행하기 위해 `cron`과 `at` 도구를 사용합니다.
* **cron:** 주기적으로 반복되는 작업을 설정할 때 사용하는 도구이며, 관련 백그라운드 서비스(데몬)인 `crond`를 통해 시스템 레벨에서 주기적인 작업을 관리합니다.
* **at:** 주기적이지 않고, 향후 특정 시점에 **딱 한 번만 실행되는 일회성 작업**을 예약할 때 사용합니다.

### 🔄 cron을 이용한 정기적 작업 예약
* **서비스 상태 확인:** `systemctl status cron` 명령어로 현재 cron 서비스가 정상 작동 중인지 확인할 수 있습니다.
* **작업 예약 방법:** `/etc/crontab` 파일을 수정하여 주기적인 작업을 등록합니다.

> 📅 **cron 주기 설정 형식**
> ```text
> * * * * * [사용자명]  [실행할 명령어]
> ┬   ┬   ┬   ┬   ┬
> │   │   │   │   │
> │   │   │   │   └─ 요일 (0 - 7, 0과 7은 일요일)
> │   │   │   └─ 월 (1 - 12)
> │   │   └─ 일 (1 - 31)
> │   └─ 시 (0 - 23)
> └─ 분 (0 - 59)
> ```
> * **예시:** 매일 새벽 4시 30분에 백업 스크립트를 실행하고 싶다면?
>   `30 4 * * * root /root/backup.sh`

### 🎯 at 명령어를 활용한 일회성 작업 예약
* **작업 예약하기:** `at [실행시간]` 형식으로 명령어를 입력하면 예약 프롬프트가 활성화됩니다. 수행할 명령어를 줄바꿈하며 입력한 뒤, **`Ctrl + D`**를 눌러 예약을 완료합니다.
  * *예시:* `at 4:00 PM` 또는 `at now + 2 hours`
* **예약 목록 확인:** `at -l` 또는 `atq` 명령어를 통해 현재 대기 중인 예약 작업 리스트를 확인할 수 있습니다.
* **예약 취소하기:** 작업을 취소하고 싶을 때는 `atrm [작업번호]`를 입력하여 특정 예약을 삭제합니다.

## 🌐 12. 네트워크 관련 설정과 명령어

### 📌 네트워크의 기본 개념
컴퓨터 네트워크를 구성하고 소통하기 위한 가장 핵심적인 요소들입니다.
* **TCP/IP:** 컴퓨터와 컴퓨터 간의 원활한 소통을 가능하게 하는 공통의 통신 규약(언어)입니다.
* **호스트 이름(Hostname):** 네트워크 상에서 각 컴퓨터가 가지는 고유한 이름입니다.
* **IP 주소:** 컴퓨터의 랜 카드(네트워크 인터페이스)에 할당된 전 세계 유일한 식별 주소입니다.
* **게이트웨이(Gateway):** 서로 다른 네트워크 간의 데이터를 전송하고 연결해 주는 필수 관문 장비입니다.

### ⚙️ 네트워크 관리 및 주요 구성 파일
* **DNS(Domain Name System) 서버:** 우리가 브라우저에 입력하는 URL(예: google.com)을 컴퓨터가 실제 인식할 수 있는 IP 주소로 변환해 주는 핵심 서버입니다.
* **넷플랜(Netplan) 설정:** 우분투 리눅스에서 네트워크 설정 정보는 주로 `/etc/netplan/` 디렉터리 내의 **YAML 파일**(`*.yaml`)에 저장되어 관리됩니다.
* **DNS 정보 파일:** `/etc/resolv.conf` 파일에서 실시간 DNS 정보를 관리합니다. 
  > ⚠️ **주의:** `/etc/resolv.conf` 파일은 시스템 재부팅 시 초기화될 수 있으므로, 영구적인 DNS 설정을 위해서는 Netplan 등 올바른 설정 파일을 수정해야 합니다.

### 💻 실습: 네트워크 설정 변경과 상태 진단
네트워크 연결 상태를 확인하고 문제를 해결할 때 사용하는 필수 명령어와 도구입니다.

* **네트워크 카드 상태 확인 (CLI):** `ip a` 또는 `ip address`
  * 텍스트 기반 서버 환경에서 현재 네트워크 카드의 IP 할당 상태를 즉시 확인할 수 있습니다.
* **네트워크 연결 진단:** `ping [목적지 IP 또는 도메인]`
  * 대상 서버와 정상적으로 데이터를 주고받을 수 있는지 응답 여부를 확인합니다.
* **DNS 작동 상태 점검:** `nslookup [도메인]`
  * 만약 웹 접속이 되지 않는 상황이라면 DNS 설정 오류를 의심해야 합니다. `nslookup`을 통해 도메인이 IP로 잘 변환되는지 확인하고, 필요 시 구글 공용 DNS(`8.8.8.8`) 등으로 테스트하여 현재 DNS 서버의 자체 문제 여부를 파악할 수 있습니다.
* **네트워크 GUI 편집기:** `nm-connection-editor`
  * 데스크톱(GUI) 환경에서 IP 주소나 DNS 정보를 그래픽 창을 통해 손쉽게 수정할 수 있도록 도와줍니다.


## 쉼표(,)와 파이프(|)로 연결하는 리눅스 프로세스 및 서비스 관리

### 🔗 명령어 연결과 데이터 처리를 위한 파이프, 필터, 리디렉션
리눅스는 복잡한 작업을 효율적으로 수행하기 위해 여러 명령어를 조합하여 사용합니다.

* **파이프 (`|`):** 두 개의 프로그램을 연결하는 통로 역할을 하며, 앞선 명령어의 출력 결과를 다음 명령어의 입력으로 전달합니다.
  * *예시:* `ls -l | less` (긴 출력 내용을 한 페이지씩 끊어서 가독성 있게 확인)
* **필터 (Filter):** 필요한 데이터만 추출하는 명령어 도구 모음입니다. (`grep`, `tail`, `wc` 등)
* **리디렉션 (`>` / `>>`):** 표준 입출력의 방향을 화면이 아닌 파일로 돌려줍니다. 결과값을 모니터에 출력하는 대신 파일에 저장하거나 추가하는 등 유연한 데이터 처리가 가능합니다.

### ⚙️ 프로세스(Process)의 개념과 상태 관리
* **정의:** 하드디스크에 저장되어 있는 실행 코드 파일(프로그램)이 메모리에 로딩되어 활성화된 상태를 의미합니다.
* **특징:** 모든 프로세스는 고유한 **PID(프로세스 ID)**를 가지며, 부모 프로세스가 종료되면 관련된 자식 프로세스도 함께 종료되는 유기적인 관계를 갖습니다.
* **프로세스 조회:** `ps -ef` 명령어를 통해 현재 시스템에서 실행 중인 프로세스의 상태를 상세히 확인할 수 있습니다.
* **프로세스 강제 종료:** 불필요하거나 응답이 없는 프로세스는 `kill -9 [PID]` 명령어로 강제 종료할 수 있습니다.

### 🔄 포그라운드와 백그라운드의 프로세스 제어
사용자는 터미널 환경에서 작업의 성격에 따라 프로세스의 실행 모드를 자유롭게 전환할 수 있습니다.

* **포그라운드(Foreground):** 화면에 상주하며 사용자와 직접 대화하는 프로세스 모드입니다.
* **백그라운드(Background):** 보이지 않는 곳에서 묵묵히 실행되는 모드로, 명령어 뒤에 `&`를 붙여 실행하면 처음부터 백그라운드로 구동됩니다. (예: `sh script.sh &`)

> 🕹️ **프로세스 제어 단축키 및 명령어**
> * **`Ctrl + Z`**: 현재 포그라운드에서 실행 중인 프로세스를 일시 정지합니다.
> * **`bg`**: 일시 정지된 프로세스를 백그라운드로 전환하여 터미널을 다시 사용할 수 있도록 만듭니다.
> * **`fg`**: 백그라운드에서 돌고 있는 프로세스를 다시 화면(포그라운드)으로 가져옵니다.

### 🌐 서비스(Service)와 소켓(Socket)의 정의와 차이점
시스템이 시작될 때 독립적으로 구동되는 서버 프로그램(데몬)은 크게 서비스와 소켓 두 가지 방식으로 나뉩니다.

| 분류 | 상주 여부 | 특징 및 장단점 | 주요 예시 |
| :--- | :--- | :--- | :--- |
| **서비스 (Service)** | 항상 실행 (`Active`) | 웹 서버나 DB 서버처럼 **즉각적인 응답이 필요할 때** 사용하며, 상시 메모리를 차지합니다. | Apache, Nginx, MySQL 등 |
| **소켓 (Socket)** | 요청 시 실행 (`In-active` 대기) | 평소에는 대기(Listen)하다가 **외부의 특정 요청이 있을 때만** 시스템에 의해 구동됩니다. 메모리를 효율적으로 쓰지만, 초기 연결 속도가 다소 느릴 수 있습니다. | SSH, FTP 관련 일부 소켓 등 |






### 🛠️ 서비스 관리하기
> 💡 **서비스(Service)란?** 사용자가 로그인하지 않아도 시스템 백그라운에서 지속적으로 실행되는 프로그램입니다. (예: nginx, ssh, mysql, docker 등)

#### 1) systemd 개요
* Ubuntu의 기본 시스템 관리자입니다.
* 서비스의 시작/중지, 부팅 시 자동 실행, 로그 관리, 시스템 상태 관리가 주요 역할입니다.

#### 2) systemctl 상태 조회
서버 장애 발생 시 서비스가 살아있는지 확인하는 것이 가장 첫 단계이므로 매우 중요합니다.
* `systemctl status nginx` : 특정 서비스(예: nginx)의 현재 상태 보기
* `systemctl list-units --type=service` : 시스템에 등록된 전체 서비스 목록 확인

#### 3) 서비스 제어
실무에서 소스 배포나 설정 변경을 진행한 후 서비스를 재시작하는 흐름이 가장 중요하게 사용됩니다.
* `sudo systemctl start nginx` : 서비스 시작
* `sudo systemctl stop nginx` : 서비스 중지
* `sudo systemctl restart nginx` : 서비스 재시작 (**★배포 후 설정 적용 시 가장 중요**)
* `sudo systemctl enable nginx` : 시스템이 부팅될 때 자동으로 서비스가 실행되도록 등록
* `sudo systemctl disable nginx` : 부팅 시 자동 실행 해제

#### 4) journalctl 로그 조회
`systemd` 기반 시스템 환경에서 발생하는 로그를 확인하는 전용 도구입니다.
* `journalctl` : 시스템의 전체 로그 확인
* `journalctl -u nginx` : 특정 서비스(예: nginx)와 관련된 로그만 필터링하여 확인
* `journalctl -f` : 로그의 마지막 부분을 실시간으로 모니터링 (오류 디버깅 및 장애 확인용)

### 📝 vi/vim 편집기 익히기
우분투 및 리눅스 환경에서 텍스트 기반 파일을 수정할 때 가장 범용적으로 사용하는 편집기입니다. (우분투에서는 기능이 향상된 `vim`을 주로 사용합니다.)

#### 1) vi의 3가지 핵심 모드
* **명령 모드 :** 파일 실행 시 최초 상태. 커서 이동, 삭제, 복사 등이 가능합니다.
* **입력 모드 :** 실제 글자를 입력할 수 있는 상태입니다.
* **ex 모드 :** 저장, 종료, 검색 등을 수행하는 모드입니다. (명령 모드에서 `:` 입력 시 진입)

#### 2) 핵심 단축키 요약 (명령 모드 기준)
* `i` : 현재 커서 위치에서 **입력 모드**로 진입
* `ESC` : 입력 모드나 ex 모드에서 다시 **명령 모드**로 복귀
* `dd` : 커서가 위치한 **한 줄 삭제**
* `yy` : 커서가 위치한 **한 줄 복사**
* `p` : 복사하거나 삭제한 한 줄을 커서 아래에 **붙여넣기**
* `u` : 직전에 실행한 작업 **실행 취소** (Undo)

#### 3) 파일 작성 및 관리 프로세스
* `vim test.txt` : `test.txt` 파일을 열거나, 없는 경우 새로 생성하면서 편집기 실행
* 입력 모드(`i`)로 전환 후 내용 작성 -> 작성 완료 후 `ESC`를 눌러 명령 모드로 복귀 -> `:`를 눌러 ex 모드로 전환 후 저장/종료 명령 입력

#### 4) 주요 ex 모드 명령 종류
* `:w` : 작업 내용 저장
* `:q` : 변경 사항이 없을 때 편집기 종료
* `:wq` : **작업 내용 저장 후 완전히 종료**
* `:q!` : 변경 사항을 저장하지 않고 **강제 종료**


## 4. 리눅스 가상화 시스템 핵심 정리

### 🌐 가상화 (Virtualization) 란?
* 하나의 실제 컴퓨터(물리 서버) 안에서 독립적으로 작동하는 여러 개의 **"가상 컴퓨터(Virtual Machine)"**를 만드는 기술입니다.
* **클라우드와의 연결:** 우리가 흔히 쓰는 AWS EC2, Naver Cloud Server, Azure VM 등이 모두 이 가상화 기술로 만들어진 가상 머신(VM)입니다. 따라서 VM을 이해하는 것은 클라우드의 가장 기본이자 핵심입니다.

---

### 🐧 리눅스 가상 시스템과 핵심 기술

#### 1) 리눅스 가상 시스템
* 실제 하나의 명품 하드웨어 컴퓨터 안에 또 다른 가상 컴퓨터들을 운영체제(OS) 독립적으로 띄워 사용할 수 있게 만드는 시스템입니다.

#### 2) KVM (Kernel-based Virtual Machine)
* **Linux 커널 내부에 기본적으로 포함된 가상화 기능**입니다.
* Linux 운영체제 자체를 강력한 가상 머신 서버(Hypervisor)로 전환해 주는 핵심 기술입니다.

#### 3) 하이퍼바이저 (Hypervisor)
* 가상 머신(VM)을 생성하고, 실행하고, 관리하는 가상화 솔루션/소프트웨어 기술을 뜻합니다.
* **대표적인 종류:** VMware, Hyper-V, KVM, VirtualBox 등

---

### 🏗️ 리눅스 가상 시스템 구조
리눅스 가상화 환경은 아래와 같은 계층 구조를 가집니다. (VM은 게스트 OS 전체를 가상화하는 구조입니다.)

* **구조도:** 하드웨어(물리 서버) ➡️ Linux Kernel + KVM ➡️ 가상 머신(VM) ➡️ 가상 OS (Ubuntu / Rocky Linux 등)


## 5. 파일 시스템 및 스토리지 관리

### 💾 파일 시스템 개요
* **정의:** 리눅스가 디스크(저장장치)를 어떻게 인식하고 사용하는지 다루는 영역입니다.
* **실무적 중요성:** 클라우드/서버 환경에서는 디스크 용량 부족, 서버 저장 공간 추가, 로그 용량 증가, DB 저장 공간 확장 문제가 자주 발생하므로, 서버 저장 공간 관리 능력을 기르는 것은 인프라 운영의 핵심 주제입니다.
* **스토리지 연결 프로세스:** `디스크 추가` ➡️ `파티션 생성` ➡️ `파일 시스템 생성` ➡️ `마운트(Mount)` ➡️ `최종 사용 가능`

---

### 🧱 파티션과 파일 시스템 개념

#### 1) 파티션 (Partition)
* 디스크를 여러 개의 독립적인 논리 공간으로 나누는 작업입니다.
* 영역별로 데이터를 분리하여 관리하기 때문에 시스템의 안전성이 올라가고 운영 편의성이 생깁니다.

#### 2) 파일 시스템 (File System)
* 저장 장치에 데이터를 저장하고 관리하는 정렬 방식입니다.
* **운영체제별 종류:** Windows는 `NTFS`를 주로 사용하며, Linux는 `ext4`, `xfs` 등을 사용합니다.

---

### 🔍 디스크 및 파일 시스템 상태 확인

#### 1) 파티션 정보 확인
* `lsblk` : 시스템에 연결된 디스크의 전체적인 구조와 트리 형태 정보 확인
* `df -h` : 마운트된 디스크의 현재 사용량 및 남은 공간을 보기 쉬운 단위(`-h`)로 확인

#### 2) 파일 시스템 상태 확인
* `fsck [장치명]` : 파일 시스템의 결함이나 이상 여부를 확인하고 검사하는 도구

---

### 🔗 마운트(Mount) 및 자동 연결 설정

#### 1) 마운트 (Mount)
* 외부 디스크(장치 파일)를 Linux 시스템 내부의 특정 디렉터리에 연결하여 사용할 수 있도록 매핑하는 작업입니다.
* **명령어 예시:** `/dev/sdb1` 장치를 `/data` 디렉터리에 연결할 때
  ```bash
  sudo mount /dev/sdb1 /data

#### 2) fstab (/etc/fstab)
* 시스템이 부팅될 때 디스크를 자동으로 마운트해 주는 설정 파일입니다.
* 매번 서버를 켤 때마다 일일이 수동으로 `mount`하기 귀찮으므로, 부팅 시 자동 연결을 위해 해당 파일에 등록하여 사용합니다.

---

### 🎛️ LVM (Logical Volume Manager)
* **정의:** Linux 및 다른 유닉스 계열 시스템에서 디스크 파티션을 유연하게 관리하기 위한 스토리지 관리 소프트웨어입니다.
* **주요 특징:**
  * 물리 디스크 구조를 추상화하여 논리 볼륨(Logical Volume) 단위로 나누어 관리합니다.
  * 고정된 일반 파티션 구조와 달리, 시스템 운영 중에도 서비스 중단 없이 **동적 확장·축소**가 가능합니다.
  * 디스크 백업 및 복구를 위한 **스냅샷 기능**을 지원합니다.
  * 시스템 관리자에게 기존 파티션 방식보다 훨씬 유연하고 강력한 저장 공간 제어 능력을 제공합니다.
