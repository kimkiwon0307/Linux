# 우분투 리눅스

<details>
<summary><h2>1장. 실습 환경 구축</h2></summary>

> **개요:** 리눅스 실습의 기반이 되는 가상화 개념을 이해하고, VMware Workstation을 활용한 가상머신 환경 구축 및 특징을 학습합니다.

---

### 1.1 가상머신 소개와 설치

#### 1.1.1 가상머신 소개
* **가상화 (Virtualization):** 실제 컴퓨터 한 대를 여러 대처럼 효율적으로 나누어 쓰기 위해 탄생한 기술입니다.
* **가상머신 (VM, Virtual Machine):** 실제 컴퓨터 1대 안에서 동시에 독립적으로 실행되는 가상 컴퓨터들을 의미합니다. (ex. Ubuntu, Rocky Linux, Windows Server 등)

#### 1.1.2 가상머신과 가상머신 소프트웨어
* **하이퍼바이저 (Hypervisor):** 가상머신(VM)을 생성하고 관리하는 프로그램입니다.
* **대표 제품군:** `VMware`, `Hyper-V`, `KVM`, `VirtualBox`
* *참고:* 실무에서 가장 사용률과 선호도가 높은 **VMware**를 기준으로 실습을 진행합니다.

#### 1.1.3 VMware Workstation Pro 설치
* VM 생성 및 삭제, 복사, 네트워크 관리, 스냅샷 관리 등 가상 인프라 전반을 제어하는 핵심 도구입니다.

---

### 1.2 가상머신 생성

#### 1.2.1 가상머신의 구조
가상머신은 실제 물리 컴퓨터의 자원을 빌려와 가짜 하드웨어를 구성하는 원리로 동작하며, 구조적으로 완벽히 매칭됩니다.

| 실제 컴퓨터 자원 | 가상 머신 (VM) 자원 |
| :--- | :--- |
| CPU | **vCPU** (Virtual CPU) |
| RAM | **vRAM** (Virtual RAM) |
| SSD / HDD | **vDISK** (Virtual Disk) |
| NIC (랜카드) | **vNIC** (Virtual Network Interface Card) |

#### 1.2.2 가상머신 만들기
* **프로비저닝 (Provisioning):** VM을 생성할 때 하드웨어 자원(CPU, RAM, Disk, Network)과 설치할 운영체제(OS ISO 파일)를 할당하고 준비하는 일련의 과정을 말합니다.

---

### 1.3 VMware의 핵심 특징

1. **격리성 (Isolation):** VM(Ubuntu) 내부가 바이러스나 오류로 망가지더라도 호스트 PC(Windows)에는 전혀 영향을 주지 않습니다.
2. **복제 (Clone):** 이미 구성이 완료된 서버 환경을 그대로 복사하여 똑같은 서버를 빠르게 찍어낼 수 있습니다.
3. **스냅샷 (Snapshot):** 현재 정상적인 서버 상태를 저장(백업)해 두고, 문제 발생 시 언제든 해당 시점으로 되돌릴 수 있습니다.
4. **다중 실행:** 컴퓨터 한 대의 자원을 나누어 여러 서버(Web, DB, DNS 서버 등)를 동시에 띄우고 테스트할 수 있습니다.

---

### 1.4 원활한 실습 준비

#### 1.4.1 VMware 단축키 (Hot Key)
* `Ctrl + G` : 호스트(Windows)에서 VM 화면 안으로 마우스/키보드 제어권 넘기기
* `Ctrl + Alt` : VM 안에서 빠져나와 호스트(Windows)로 제어권 돌리기

#### 1.4.2 종료 옵션 (전원 관리)
* **Suspend (일시정지):** 현재 작업 상태를 그대로 메모리에 저장하고 멈춥니다. 빠른 재개에 유용합니다.
* **Power Off (강제 종료):** 실제 컴퓨터의 전원 플러그를 뽑는 것과 같으므로 데이터 유실에 주의해야 합니다.

#### 1.4.3 전체 화면 사용 및 여러 VM 동시 실행 기능 활용
* 실무 환경과 유사한 다중 서버 아키텍처 구성을 위해 여러 VM을 동시에 제어하는 방법을 숙지합니다.

#### 1.4.4 가상 네트워크 종류 파악

| 종류 | 인터넷 연결 여부 | 특징 및 통신 범위 | 
| :--- | :---: | :--- |
| **Bridged** | ⭕ 가능 | 실제 PC와 동일한 네트워크 대역의 IP를 공유기에서 직접 할당받음. PC와 VM이 대등한 독립 장비로 동작. |
| **NAT** | ⭕ 가능 | **[실습 주력]** 호스트 PC 내부 IP를 공유받아 사용. VM에서 인터넷은 가능하나, 외부에서 VM으로의 직접 접근은 차단되어 보안상 유리. |
| **Host-Only** | ❌ 불가 | 외부 인터넷과 단절된 폐쇄망 구축 시 사용. 호스트 PC와 가상머신들 사이에서만 내부 통신 가능. |

#### 1.4.5 파일 전송 방법 (Windows ➔ Linux)
1. Drag & Drop (드래그 앤 드롭)
2. Shared Folder (VMware 공유 폴더 설정)
3. **SCP** (Secure Copy Protocol) 🌟 *실무 다빈도*
4. **WinSCP** (GUI 기반의 FTP/SFTP 클라이언트 프로그램) 🌟 *실무 다빈도*

<summary><h2>2장. 우분투 리눅스 소개</h2></summary>

> **개요:** 리눅스의 탄생 배경과 핵심 구성 요소인 커널(Kernel) 및 셸(Shell)의 개념을 이해하고, 우분투 배포판의 특징과 주요 패키지를 학습합니다.

---

### 2.1 리눅스의 개요

#### 2.1.1 리눅스의 탄생
* **초기 컴퓨터:** 운영체제(OS)가 없어 하드웨어에 프로그램을 직접 입력해야 하는 극심한 불편함이 존재했습니다.
* **UNIX의 등장:** 안정성, 멀티태스킹, 다중 사용자 지원을 무기로 혁명을 일으켰으나, 지나치게 높은 비용이 단점이었습니다.
* **Linux의 탄생:** 리누스 토발즈(Linus Torvalds)라는 대학생이 유닉스를 기반으로 취미 삼아 무료 운영체제 핵심인 **Linux Kernel**을 개발했습니다.
* **성공 요인:** 무료 이용 가능, 소스 코드 완전 공개(Open Source), 전 세계 개발자의 자유로운 수정 및 기여가 가능했기 때문입니다.

#### 2.1.2 GNU 프로젝트
* **개념:** "모든 사람이 자유롭게 사용할 수 있는 소프트웨어 생태계를 만들자"는 이념으로 시작된 프로젝트입니다.
* **성공과 공백:** `bash`, `gcc`, `gdb`, `coreutils` 등 운영체제에 필요한 핵심 도구들을 완벽히 만들었으나, 정작 시스템을 조율할 '커널'이 완성되지 못한 상태였습니다.
* **완성:** GNU의 다양한 오픈소스 도구들과 리누스 토발즈가 만든 **Linux Kernel**이 결합하면서 오늘날 우리가 사용하는 완전한 형태의 리눅스 OS가 완성되었습니다.

#### 2.1.3 커널 (Kernel)
* **정의:** 운영체제의 핵심이자 하드웨어를 직접 제어하고 관리하는 '컴퓨터의 최상위 관리자'입니다.
* **셸(Shell)의 필요성:** 사용자는 커널에게 직접 명령을 내릴 수 없습니다. 따라서 중간에서 사용자의 명령을 커널이 이해할 수 있도록 번역해 주는 **통역사 역할의 Shell**이 반드시 필요합니다.

> **💡 명령어 처리 흐름 예시**
> `사용자` ➔ `Shell (ls 입력)` ➔ `Kernel` ➔ `하드웨어 (디스크 조회)` ➔ `결과 화면 출력`

* **커널의 5대 핵심 역할:**
  1. **CPU 관리:** 어떤 프로그램에 CPU 연산 자원을 우선 배정할지 결정
  2. **메모리 관리:** 각 프로그램에 RAM 공간을 안전하게 할당하고 회수
  3. **파일 관리:** 디스크 저장 장치에 파일을 읽고 쓰는 권한 및 구조 제어
  4. **네트워크 관리:** TCP/IP 프로토콜 스택 처리 및 데이터 송수신 관리
  5. **장치 관리:** USB, SSD, 랜카드(NIC), 프린터 등 물리 장치 드라이버 제어

---

### 2.2 우분투 리눅스 배포판
* **배포판(Distribution)이란?** 리눅스 커널 자체만으로는 일반 사용자가 쓸 수 없기 때문에, `커널 + 명령어 + 패키지 관리자 + 설치 프로그램 + GUI`를 하나로 묶어 구성한 완전한 운영체제 패키지입니다. (ex. Ubuntu, Debian, Rocky Linux, AlmaLinux, Fedora 등)

#### 2.2.1 데비안과 우분투
우분투는 데비안(Debian) 리눅스를 모태로 하여 파생된 배포판입니다.
* **Debian 특징:** 철저한 검증을 거치므로 매우 안정적이고 보수적이지만, 패키지 업데이트가 상대적으로 느립니다.
* **Ubuntu 특징:** 초보자도 접근하기 쉬우며, 최신 패키지를 빠르게 제공하고 전 세계적으로 참고할 수 있는 문서(커뮤니티)가 가장 방대합니다.

#### 2.2.2 우분투 배포판 종류
* **Ubuntu Desktop:** GUI(그래픽 화면)가 기본 포함되어 윈도우처럼 마우스로 조작 가능한 버전입니다.
* **Ubuntu Server:** GUI가 제외된 CLI(텍스트 터미널) 기반으로 작동하며, 서버 자원 낭비를 최소화하여 성능을 극대화한 버전입니다.

#### 2.2.3 우분투 버전 규칙
* **버전 명명:** `YY.MM` 형태로 출시 연도와 월을 나타냅니다. (ex. Ubuntu 24.04는 2024년 4월 출시 제품)
* **LTS (Long Term Support):** 2년마다 출시되는 **장기 지원 버전**으로, 성능이 안정적이고 기술 지원 기간이 길어 기업 실무 환경에서는 대부분 LTS 버전을 채택합니다.

#### 2.2.4 Ubuntu 24.04 설치 요구사항
* **CPU:** 2 Core 이상
* **RAM:** 4GB 이상
* **Disk:** 25GB 이상의 여유 공간

#### 2.2.5 우분투 주요 패키지 요약

| 패키지 명 | 주요 역할 및 특징 |
| :--- | :--- |
| **Bash** | 우분투의 기본 셸(Shell)로 명령어 해석 및 스크립트 실행 담당 |
| **OpenSSH** | 원격지에서 리눅스 서버에 안전하게 암호화 접속하기 위한 필수 보안 프로토콜 |
| **systemd** | 리눅스 부팅 시 시스템 서비스(데몬)들을 전체적으로 제어하고 관리하는 최상위 프로세스 |
| **APT** | 우분투 전용 패키지 관리 도구로, 인터넷을 통해 소프트웨어를 쉽게 설치/삭제 가능 |
| **Vim** | CLI 환경에서 가장 널리 쓰이는 강력한 기본 텍스트 편집기 |
| **Netplan** | 우분투의 최신 네트워크 설정 도구 (`/etc/netplan/` 경로의 YAML 파일로 IP/DNS 관리) |
</details>

<summary><h2>3장. 서버 구축 시 알아야 할 필수 개념과 명령어</h2></summary>

> **개요:** 리눅스 서버 운영의 기본이 되는 전원 관리, 가상 콘솔, 디렉터리 구조, 기본 도구(에디터/마운트) 및 필수 명령어들을 학습합니다.

---

### 3.1 리눅스 운영에서 먼저 알아야 할 개념

#### 3.1.1 시작과 종료
* **시스템 즉시 종료:** `sudo shutdown now`
* **전원 종료:** `sudo poweroff`
* **종료 예약 (10분 뒤):** `sudo shutdown -h +10`
* **예약된 종료 취소:** `sudo shutdown -c`

#### 3.1.2 시스템 재부팅
* **언제 하는가?** 커널 업데이트 적용, 주요 네트워크 설정 변경, 시스템 장애 복구 시 수행합니다.
* **명령어:** `sudo reboot` 또는 `sudo shutdown -r now`

#### 3.1.3 로그아웃 (Logout)
* **개념:** 시스템 자체를 끄지 않고, 현재 로그인된 사용자 세션만 안전하게 종료합니다.
* **명령어:** `exit` 또는 `logout`

#### 3.1.4 가상 콘솔 (Virtual Console)
* 하나의 화면만 사용하는 윈도우와 달리, 리눅스는 하나의 모니터(컴퓨터)에서 여러 개의 독립된 터미널 창을 전환하며 사용할 수 있는 가상 콘솔 기능을 지원합니다.

#### 3.1.5 리눅스 디렉터리 구조 (FHS)
리눅스는 모든 파일과 디렉터리가 최상위 루트(`/`)를 기점으로 역트리(Tree) 구조를 이룹니다.

| 디렉터리 | 주요 역할 및 저장 데이터 |
| :--- | :--- |
| **`/`** | **최상위 루트 디렉터리**, 모든 절대 경로의 시작점 |
| **`/home`** | 일반 사용자들의 개인 홈 디렉터리 공간 |
| **`/root`** | 최상위 관리자(root) 전용 홈 디렉터리 |
| **`/etc`** | 시스템 및 각종 애플리케이션의 **핵심 설정 파일** 저장소 |
| **`/var`** | 시스템 로그, 데이터베이스 파일 등 **동적으로 변하는 데이터** 저장 |
| **`/tmp`** | 시스템 및 프로그램이 사용하는 임시 파일 저장소 |
| **`/usr`** | 일반 사용자들이 실행하는 프로그램 및 유틸리티 저장 설치 경로 |
| **`/bin`** | 시스템의 필수 기본 명령어 모음 (`ls`, `cp`, `mv`, `cat` 등) |
| **`/dev`** | 하드웨어 장치들을 파일 형태로 관리하는 장치 파일 저장소 |
| **`/proc`** | RAM에 상주하는 커널 정보 및 실시간 시스템 정보(가상 파일 시스템) |

#### 3.1.6 런레벨 (Runlevel)
* **개념:** 현재 우분투 등 최신 리눅스에서는 **`systemd` 인프라의 Target 개념으로 대체**되어 사용됩니다.

#### 3.1.7 자동 완성과 히스토리
* **`TAB` 키:** 파일명, 디렉터리명, 명령어 등을 입력할 때 자동으로 완성해 주는 필수 기능입니다.
* **`history`:** 이전에 실행했던 명령어 기록들을 번호 순으로 조회합니다.

#### 3.1.8 에디터 사용
* **`nano`:** 다루기 쉽고 직관적인 텍스트 에디터입니다.
* **`vi` / `vim`:** 리눅스 환경의 실무 표준 에디터입니다.
  * **입력 모드 전환:** `i`
  * **명령 모드 복귀:** `ESC`
  * **저장 후 종료:** `:wq`
  * **저장하지 않고 강제 종료:** `:q!`

#### 3.1.9 도움말 사용법
* **`man [명령어]`:** 특정 명령어의 사용법, 옵션, 매뉴얼 페이지를 상세히 확인합니다.

#### 3.1.10 마운트(Mount)와 스토리지 활용

<summary><h2>4장. 하드디스크 관리와 사용자별 공간 할당</h2></summary>

> **개요:** 리눅스 환경에서 물리 디스크를 추가하고, 파티션 분할, 포맷, 마운트를 통해 실제 저장 공간으로 사용하는 일련의 과정을 학습합니다.

---

### 4.1 디스크 1개 추가하기
> **전체 작업 프로세스:** 리눅스에서 새로운 스토리지를 확장할 때는 항상 아래의 순서대로 명확히 정형화된 단계를 거쳐야 합니다.
> `디스크 장치 추가` ➔ `파티션(Partition) 생성` ➔ `파일 시스템 생성(포맷)` ➔ `디렉터리 마운트` ➔ `사용 가능`

* **실무 예시:** 운영 중인 리눅스 서버에서 로그 파일 누적, 데이터베이스(DB) 용량 증가, 혹은 유저 업로드 파일 급증으로 디스크 공간이 부족해질 때 새로운 물리/가상 디스크를 장착하고 수동으로 인식시켜 공간을 확장합니다.

---

#### 4.1.1 SATA 장치와 SCSI 장치 구성
리눅스 커널은 저장장치 인터페이스 종류(SATA, SCSI, NVMe 등)에 따라 일관된 디바이스 파일 이름 규칙을 부여하여 관리합니다.

* **인터페이스 종류:**
  * **SATA:** 일반 PC 및 보급형 서버에서 오랫동안 널리 쓰인 규격입니다.
  * **SCSI:** 엔터프라이즈 서버 및 고성능 환경에서 주로 사용하는 안정적인 규격입니다.
* **디스크 장치 이름 식별 규칙:**
  * 첫 번째 디스크 장치: `/dev/sda`
  * 두 번째 디스크 장치: `/dev/sdb`
  * 세 번째 디스크 장치: `/dev/sdc`
* **파티션 분할 이름 식별 규칙:**
  * 하나의 물리 디스크를 논리적으로 분할하면 이름 뒤에 숫자가 붙습니다.
  * (ex) `/dev/sda1`, `/dev/sda2` ➔ `sda` 디스크의 1번 파티션, 2번 파티션을 의미
* **💡 실무 분할 예시:** 100GB 용량의 전체 디스크가 있을 때 이를 통째로 쓰지 않고, 안정적인 관리를 위해 `50GB는 OS 영역`, 나머지 `50GB는 DATA 저장 영역`으로 분리하여 파티셔닝합니다.

##### 🛠️ 디스크 모니터링 관련 핵심 명령어
* **`lsblk`**: 시스템에 연결된 블록 장치(디스크 및 파티션)의 트리 구조와 연결 상태를 트리 형태로 간단히 확인합니다.
* **`sudo fdisk -l`**: 상세 디스크 크기, 실질적인 파티션 테이블 유형, 용량 및 섹터 정보까지 깊이 있게 스캔합니다.

---

#### 4.1.2 디스크 추가 및 인식 실습 6단계

| 단계 | 수행 작업 | 핵심 명령어 | 주요 목적 |
| :--- | :--- | :--- | :--- |
| **1단계** | **파티션 분할** | `fdisk /dev/sdb` | 새로 추가된 `sdb` 디스크 내부에 논리적 구역(Partition) 정의 |
| **2단계** | **파일 시스템 포맷** | `mkfs.ext4 /dev/sdb1` | 생성된 파티션 영역을 리눅스 표준 파일 시스템(`ext4`)으로 포맷 |
| **3단계** | **마운트 포인트 준비** | `mkdir /data` | 디스크 공간을 운영체제와 연결해 줄 타깃 빈 폴더 생성 |
| **4단계** | **디렉터리 마운트** | `mount /dev/sdb1 /data` | 포맷된 디스크 장치 파티션을 새로 만든 `/data` 폴더에 일시적 결합 |
| **5단계** | **fstab 영구 등록** | `vi /etc/fstab` | 서버가 재부팅되어도 자동으로 마운트가 유지되도록 설정 파일에 등록 |
| **6단계** | **최종 용량 검증** | `df -h` | 디스크 용량과 마운트 상태를 사람이 읽기 쉬운 단위(GB/MB)로 최종 확인 |


##### 💡 5단계: /etc/fstab 등록 서식 및 테스트
```text
# [UUID 또는 장치명]    [마운트 포인트]  [파일시스템 타입]  [옵션]    [덤프]  [파일체크순서]
UUID=a1b2c3d4-e5f6...  /data            ext4               defaults  0       2
```
* **⚠️ 재부팅 전 마운트 테스트 필수:** `/etc/fstab` 파일 설정 후 아래 명령어를 실행하여 에러가 발생하지 않는지 반드시 확인해야 부팅 불가 장애를 방지할 수 있습니다.
  ```bash
  sudo mount -a
  ```

<summary><h2>5장. 하드디스크 관리와 사용자별 공간 할당</h2></summary>

> **개요:** RAID를 통한 디스크 신뢰성 확보, LVM을 통한 유연한 볼륨 관리, 그리고 디스크 쿼터를 통한 사용자별 자원 제한 방법을 학습합니다.

---

### 5.2 RAID (Redundant Array of Independent Disks)

#### 5.2.1 RAID의 정의와 개념
* **정의:** 복수의 물리 하드디스크를 하나의 논리적인 대용량 저장 장치로 묶어서 관리하는 기술입니다.
* **핵심 목적:**
  1. **성능 향상 (Performance):** 데이터를 분산 저장하여 읽기/쓰기 속도 증대
  2. **데이터 보호 (Redundancy):** 디스크 장애 시에도 데이터 복구 및 서비스 연속성 보장

#### 5.2.2 핵심 RAID 레벨별 특징 및 비교

| RAID 레벨 | 주요 메커니즘 | 최소 디스크 | 특징 |
| :--- | :--- | :---: | :--- |
| **RAID 0** | 스트라이핑 | 2개 | 성능 극대화, 안전성 없음 |
| **RAID 1** | 미러링 | 2개 | 높은 안전성, 용량 50% 사용 |
| **RAID 5** | 패리티 분산 | 3개 | 성능/안전성 균형 (실무 최다 사용) |
| **RAID 6** | 이중 패리티 | 4개 | 디스크 2개 고장까지 보호 |
| **RAID 10** | 미러링+스트라이핑 | 4개 | 성능과 안전성 모두 최고 |

---

### 5.3 LVM (Logical Volume Manager)

#### 5.3.1 LVM의 개념
* **정의:** 물리적 하드디스크 구조에 종속되지 않고, 여러 디스크를 하나의 큰 풀(Pool)로 묶어 유연하게 용량을 조절하는 기술입니다.
* **LVM 아키텍처:** `물리 디스크(PV)` ➔ `볼륨 그룹(VG)` ➔ `논리 볼륨(LV)`
* **실무 이점:** 
  * **온라인 확장:** 서비스 중단 없이 실시간 용량 증설 가능
  * **유연성:** 파티션 크기를 자유롭게 변경 가능
  * **스냅샷:** 데이터 복구를 위한 시점 보관 기능 지원

#### 5.3.2 LVM 구현 실습 절차
| 단계 | 수행 작업 | 핵심 명령어 |
| :--- | :--- | :--- |
| **1단계** | **PV 생성** | `sudo pvcreate /dev/sdb` |
| **2단계** | **VG 생성** | `sudo vgcreate vgdata /dev/sdb /dev/sdc` |
| **3단계** | **LV 생성** | `sudo lvcreate -L 1G -n lvdata vgdata` |
| **4단계** | **포맷 및 마운트** | `mkfs.ext4`, `mount` |

---

### 5.4 디스크 쿼터 (Quota)

#### 5.4.1 쿼터의 개념
* **정의:** 특정 사용자나 그룹이 사용할 수 있는 디스크 공간 및 파일 개수를 제한하는 기능입니다.
* **필요성:** 사용자 독점 방지, 루트 디렉터리 보호, 효율적인 자원 분배.

#### 5.4.2 제한 방식
* **Soft Limit:** 경고 수준 (유예 기간 내 정리 필요)
* **Hard Limit:** 절대 제한 (초과 시 파일 저장 불가)

#### 5.4.3 설정 실습 절차
| 단계 | 작업 내용 | 실행 명령어 |
| :--- | :--- | :--- |
| **1단계** | **옵션 추가** | `/etc/fstab`에 `usrquota`, `grpquota` 추가 |
| **2단계** | **데이터베이스 생성**| `sudo quotacheck -ugm /data` |
| **3단계** | **기능 활성화** | `sudo quotaon /data` |
| **4단계** | **용량 설정** | `sudo edquota -u [사용자명]` |

<summary><h2>6장. 셸 스크립트 프로그래밍</h2></summary>

> **개요:** 리눅스의 핵심인 셸의 동작 원리를 이해하고, 자동화 스크립트를 작성하기 위한 Bash 문법(변수, 조건문, 반복문, 함수 등)을 학습합니다.

---

### 6.1 셸의 기본

#### 6.1.1 우분투의 bash 셸
* **셸(Shell):** 사용자의 명령을 해석해 커널에 전달하는 통역사.
* **Bash(Bourne Again Shell):** 리눅스 실무 표준 셸. (`echo $SHELL`로 확인 가능)

#### 6.1.2 셸의 명령문 처리
* **특수 문자:**
  * `;`: 순차 실행
  * `&&`: 앞 명령어 성공 시 실행
  * `||`: 앞 명령어 실패 시 실행
  * `|`: 파이프 (결과 전달)
* **리다이렉션:** `>` (덮어쓰기), `>>` (내용 추가)

#### 6.1.3 환경 변수
* 시스템 전체에서 참조하는 설정값. (`env`로 확인, `export`로 등록)
* **주요 변수:** `HOME`, `USER`, `HOSTNAME`, `PATH`

---

### 6.2 셸 스크립트 프로그래밍

#### 6.2.1 작성 규칙
* **쉬뱅(Shebang):** 파일 첫 줄에 `#!/bin/bash` 필수 기재.

#### 6.2.2 변수 및 연산
* **대입:** `NAME="kim"` (공백 없음)
* **호출:** `$NAME`
* **입력:** `read 변수명`
* **연산:** `$((A + B))`

#### 6.2.3 if문 (조건 처리)
* **문법:** `if [ $NUM -gt 5 ]; then ... fi` (대괄호 양 끝 공백 필수!)
* **숫자 비교:** `-eq`(같다), `-ne`(다르다), `-gt`(크다), `-lt`(작다), `-ge`(이상), `-le`(이하)

#### 6.2.4 반복문
* **for문:** `for i in {1..5}; do ... done` (지정된 범위 반복)
* **while문:** 조건이 참인 동안 반복.

#### 6.2.5 기타 유용한 개념
* **매개변수:** `$1`, `$2` 등으로 스크립트 실행 시 전달된 인자 사용.
* **함수:** 코드 묶음 처리.
* **종료 코드:** `0`(성공), `0이 아닌 값`(실패).

---

### 💡 실무 스크립트 예제

```bash
#!/bin/bash

# 변수와 입력
read -p "이름을 입력하세요: " NAME
echo "안녕하세요, $NAME님!"

# 조건문
if [ $# -eq 0 ]; then
    echo "전달된 매개변수가 없습니다."
else
    echo "전달된 매개변수 개수: $#"
fi

# 반복문
for i in {1..3}
do
    echo "반복 중... $i"
done
```
