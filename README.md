# 우분투 리눅스

## 1장. 실습 환경 구축

> **개요:** 리눅스 실습의 기반이 되는 가상화 개념을 이해하고, VMware Workstation을 활용한 가상머신 환경 구축 및 특징을 학습합니다.

---

### 1.1 가상머신 소개와 설치

#### 1.1.1 가상머신 소개
* **가상화 (Virtualization):** 실제 컴퓨터 한 대를 여러 대처럼 효율적으로 나누어 쓰기 위해 탄생한 기술입니다.
* **가상머신 (VM, Virtual Machine):** 실제 컴퓨터 1대 안에서 동시에 독립적으로 실행되는 가상 컴퓨터들을 의미합니다. (ex. Ubuntu, Rocky Linux, Windows Server 등)

#### 1.1.2 가상머신과 가상머신 소프트웨어
* **하이퍼바이저 (Hypervisor):** 가상머신(VM)을 생성하고 관리하는 프로그램입니다.
* **대표 제품군:** `VMware`, `Hyper-V`, `KVM`, `VirtualBox`
* *참고:* 실무에서 가장 사용률과 선호도가 높은 **VMware**를 기준으로 실습을 진행합니다.

#### 1.1.3 VMware Workstation Pro 설치
* VM 생성 및 삭제, 복사, 네트워크 관리, 스냅샷 관리 등 가상 인프라 전반을 제어하는 핵심 도구입니다.

---

### 1.2 가상머신 생성

#### 1.2.1 가상머신의 구조
가상머신은 실제 물리 컴퓨터의 자원을 빌려와 가짜 하드웨어를 구성하는 원리로 동작하며, 구조적으로 완벽히 매칭됩니다.

| 실제 컴퓨터 자원 | 가상 머신 (VM) 자원 |
| :--- | :--- |
| CPU | **vCPU** (Virtual CPU) |
| RAM | **vRAM** (Virtual RAM) |
| SSD / HDD | **vDISK** (Virtual Disk) |
| NIC (랜카드) | **vNIC** (Virtual Network Interface Card) |

#### 1.2.2 가상머신 만들기
* **프로비저닝 (Provisioning):** VM을 생성할 때 하드웨어 자원(CPU, RAM, Disk, Network)과 설치할 운영체제(OS ISO 파일)를 할당하고 준비하는 일련의 과정을 말합니다.

---

### 1.3 VMware의 핵심 특징

1. **격리성 (Isolation):** VM(Ubuntu) 내부가 바이러스나 오류로 망가지더라도 호스트 PC(Windows)에는 전혀 영향을 주지 않습니다.
2. **복제 (Clone):** 이미 구성이 완료된 서버 환경을 그대로 복사하여 똑같은 서버를 빠르게 찍어낼 수 있습니다.
3. **스냅샷 (Snapshot):** 현재 정상적인 서버 상태를 저장(백업)해 두고, 문제 발생 시 언제든 해당 시점으로 되돌릴 수 있습니다.
4. **다중 실행:** 컴퓨터 한 대의 자원을 나누어 여러 서버(Web, DB, DNS 서버 등)를 동시에 띄우고 테스트할 수 있습니다.

---

### 1.4 원활한 실습 준비

#### 1.4.1 VMware 단축키 (Hot Key)
* `Ctrl + G` : 호스트(Windows)에서 VM 화면 안으로 마우스/키보드 제어권 넘기기
* `Ctrl + Alt` : VM 안에서 빠져나와 호스트(Windows)로 제어권 돌리기

#### 1.4.2 종료 옵션 (전원 관리)
* **Suspend (일시정지):** 현재 작업 상태를 그대로 메모리에 저장하고 멈춥니다. 빠른 재개에 유용합니다.
* **Power Off (강제 종료):** 실제 컴퓨터의 전원 플러그를 뽑는 것과 같으므로 데이터 유실에 주의해야 합니다.

#### 1.4.3 전체 화면 사용 및 여러 VM 동시 실행 기능 활용
* 실무 환경과 유사한 다중 서버 아키텍처 구성을 위해 여러 VM을 동시에 제어하는 방법을 숙지합니다.

#### 1.4.4 가상 네트워크 종류 파악

| 종류 | 인터넷 연결 여부 | 특징 및 통신 범위 |
| :--- | :---: | :--- |
| **Bridged** | ⭕ 가능 | 실제 PC와 동일한 네트워크 대역의 IP를 공유기에서 직접 할당받음. PC와 VM이 대등한 독립 장비로 동작. |
| **NAT** | ⭕ 가능 | **[실습 주력]** 호스트 PC 내부 IP를 공유받아 사용. VM에서 인터넷은 가능하나, 외부에서 VM으로의 직접 접근은 차단되어 보안상 유리. |
| **Host-Only** | ❌ 불가 | 외부 인터넷과 단절된 폐쇄망 구축 시 사용. 호스트 PC와 가상머신들 사이에서만 내부 통신 가능. |

#### 1.4.5 파일 전송 방법 (Windows ➔ Linux)
1. Drag & Drop (드래그 앤 드롭)
2. Shared Folder (VMware 공유 폴더 설정)
3. **SCP** (Secure Copy Protocol) 🌟 *실무 다빈도*
4. **WinSCP** (GUI 기반의 FTP/SFTP 클라이언트 프로그램) 🌟 *실무 다빈도*
      
# 2장 우분투 리눅스 소개

> **개요:** 리눅스의 탄생 배경과 핵심 구성 요소인 커널(Kernel) 및 셸(Shell)의 개념을 이해하고, 우분투 배포판의 특징과 주요 패키지를 학습합니다.

---
  ### 2.1 리눅스의 개요

#### 2.1.1 리눅스의 탄생
* **초기 컴퓨터:** 운영체제(OS)가 없어 하드웨어에 프로그램을 직접 입력해야 하는 극심한 불편함이 존재했습니다.
* **UNIX의 등장:** 안정성, 멀티태스킹, 다중 사용자 지원을 무기로 혁명을 일으켰으나, 지나치게 높은 비용이 단점이었습니다.
* **Linux의 탄생:** 리누스 토발즈(Linus Torvalds)라는 대학생이 유닉스를 기반으로 취미 삼아 무료 운영체제 핵심인 **Linux Kernel**을 개발했습니다.
* **성공 요인:** 무료 이용 가능, 소스 코드 완전 공개(Open Source), 전 세계 개발자의 자유로운 수정 및 기여가 가능했기 때문입니다.

#### 2.1.2 GNU 프로젝트
* **개념:** "모든 사람이 자유롭게 사용할 수 있는 소프트웨어 생태계를 만들자"는 이념으로 시작된 프로젝트입니다.
* **성공과 공백:** `bash`, `gcc`, `gdb`, `coreutils` 등 운영체제에 필요한 핵심 도구들을 완벽히 만들었으나, 정작 시스템을 조율할 '커널'이 완성되지 못한 상태였습니다.
* **완성:** GNU의 다양한 오픈소스 도구들과 리누스 토발즈가 만든 **Linux Kernel**이 결합하면서 오늘날 우리가 사용하는 완전한 형태의 리눅스 OS가 완성되었습니다.

#### 2.1.3 커널 (Kernel)
* **정의:** 운영체제의 핵심이자 하드웨어를 직접 제어하고 관리하는 '컴퓨터의 최상위 관리자'입니다.
* **셸(Shell)의 필요성:** 사용자는 커널에게 직접 명령을 내릴 수 없습니다. 따라서 중간에서 사용자의 명령을 커널이 이해할 수 있도록 번역해 주는 **통역사 역할의 Shell**이 반드시 필요합니다.

> **💡 명령어 처리 흐름 예시**
> `사용자` ➔ `Shell (ls 입력)` ➔ `Kernel` ➔ `하드웨어 (디스크 조회)` ➔ `결과 화면 출력`

* **커널의 5대 핵심 역할:**
  1. **CPU 관리:** 어떤 프로그램에 CPU 연산 자원을 우선 배정할지 결정
  2. **메모리 관리:** 각 프로그램에 RAM 공간을 안전하게 할당하고 회수
  3. **파일 관리:** 디스크 저장 장치에 파일을 읽고 쓰는 권한 및 구조 제어
  4. **네트워크 관리:** TCP/IP 프로토콜 스택 처리 및 데이터 송수신 관리
  5. **장치 관리:** USB, SSD, 랜카드(NIC), 프린터 등 물리 장치 드라이버 제어

---

### 2.2 우분투 리눅스 배포판
* **배포판(Distribution)이란?** 리눅스 커널 자체만으로는 일반 사용자가 쓸 수 없기 때문에, `커널 + 명령어 + 패키지 관리자 + 설치 프로그램 + GUI`를 하나로 묶어 구성한 완전한 운영체제 패키지입니다. (ex. Ubuntu, Debian, Rocky Linux, AlmaLinux, Fedora 등)

#### 2.2.1 데비안과 우분투
우분투는 데비안(Debian) 리눅스를 모태로 하여 파생된 배포판입니다.
* **Debian 특징:** 철저한 검증을 거치므로 매우 안정적이고 보수적이지만, 패키지 업데이트가 상대적으로 느립니다.
* **Ubuntu 특징:** 초보자도 접근하기 쉬우며, 최신 패키지를 빠르게 제공하고 전 세계적으로 참고할 수 있는 문서(커뮤니티)가 가장 방대합니다.

#### 2.2.2 우분투 배포판 종류
* **Ubuntu Desktop:** GUI(그래픽 화면)가 기본 포함되어 윈도우처럼 마우스로 조작 가능한 버전입니다.
* **Ubuntu Server:** GUI가 제외된 CLI(텍스트 터미널) 기반으로 작동하며, 서버 자원 낭비를 최소화하여 성능을 극대화한 버전입니다.

#### 2.2.3 우분투 버전 규칙
* **버전 명명:** `YY.MM` 형태로 출시 연도와 월을 나타냅니다. (ex. Ubuntu 24.04는 2024년 4월 출시 제품)
* **LTS (Long Term Support):** 2년마다 출시되는 **장기 지원 버전**으로, 성능이 안정적이고 기술 지원 기간이 길어 기업 실무 환경에서는 대부분 LTS 버전을 채택합니다.

#### 2.2.4 Ubuntu 24.04 설치 요구사항
* **CPU:** 2 Core 이상
* **RAM:** 4GB 이상
* **Disk:** 25GB 이상의 여유 공간

#### 2.2.5 우분투 주요 패키지 요약

| 패키지 명 | 주요 역할 및 특징 |
| :--- | :--- |
| **Bash** | 우분투의 기본 셸(Shell)로 명령어 해석 및 스크립트 실행 담당 |
| **OpenSSH** | 원격지에서 리눅스 서버에 안전하게 암호화 접속하기 위한 필수 보안 프로토콜 |
| **systemd** | 리눅스 부팅 시 시스템 서비스(데몬)들을 전체적으로 제어하고 관리하는 최상위 프로세스 |
| **APT** | 우분투 전용 패키지 관리 도구로, 인터넷을 통해 소프트웨어를 쉽게 설치/삭제 가능 |
| **Vim** | CLI 환경에서 가장 널리 쓰이는 강력한 기본 텍스트 편집기 |
| **Netplan** | 우분투의 최신 네트워크 설정 도구 (`/etc/netplan/` 경로의 YAML 파일로 IP/DNS 관리) |
