# 우분투 리눅스

<details>
<summary><h2>1장. 실습 환경 구축</h2></summary>

> **개요:** 리눅스 실습의 기반이 되는 가상화 개념을 이해하고, VMware Workstation을 활용한 가상머신 환경 구축 및 특징을 학습합니다.

---

### 1.1 가상머신 소개와 설치

#### 1.1.1 가상머신 소개
* **가상화 (Virtualization):** 실제 컴퓨터 한 대를 여러 대처럼 효율적으로 나누어 쓰기 위해 탄생한 기술입니다.
* **가상머신 (VM, Virtual Machine):** 실제 컴퓨터 1대 안에서 동시에 독립적으로 실행되는 가상 컴퓨터들을 의미합니다. (ex. Ubuntu, Rocky Linux, Windows Server 등)

#### 1.1.2 가상머신과 가상머신 소프트웨어
* **하이퍼바이저 (Hypervisor):** 가상머신(VM)을 생성하고 관리하는 프로그램입니다.
* **대표 제품군:** `VMware`, `Hyper-V`, `KVM`, `VirtualBox`
* *참고:* 실무에서 가장 사용률과 선호도가 높은 **VMware**를 기준으로 실습을 진행합니다.

#### 1.1.3 VMware Workstation Pro 설치
* VM 생성 및 삭제, 복사, 네트워크 관리, 스냅샷 관리 등 가상 인프라 전반을 제어하는 핵심 도구입니다.

---

### 1.2 가상머신 생성

#### 1.2.1 가상머신의 구조
가상머신은 실제 물리 컴퓨터의 자원을 빌려와 가짜 하드웨어를 구성하는 원리로 동작하며, 구조적으로 완벽히 매칭됩니다.

| 실제 컴퓨터 자원 | 가상 머신 (VM) 자원 |
| :--- | :--- |
| CPU | **vCPU** (Virtual CPU) |
| RAM | **vRAM** (Virtual RAM) |
| SSD / HDD | **vDISK** (Virtual Disk) |
| NIC (랜카드) | **vNIC** (Virtual Network Interface Card) |

#### 1.2.2 가상머신 만들기
* **프로비저닝 (Provisioning):** VM을 생성할 때 하드웨어 자원(CPU, RAM, Disk, Network)과 설치할 운영체제(OS ISO 파일)를 할당하고 준비하는 일련의 과정을 말합니다.

---

### 1.3 VMware의 핵심 특징

1. **격리성 (Isolation):** VM(Ubuntu) 내부가 바이러스나 오류로 망가지더라도 호스트 PC(Windows)에는 전혀 영향을 주지 않습니다.
2. **복제 (Clone):** 이미 구성이 완료된 서버 환경을 그대로 복사하여 똑같은 서버를 빠르게 찍어낼 수 있습니다.
3. **스냅샷 (Snapshot):** 현재 정상적인 서버 상태를 저장(백업)해 두고, 문제 발생 시 언제든 해당 시점으로 되돌릴 수 있습니다.
4. **다중 실행:** 컴퓨터 한 대의 자원을 나누어 여러 서버(Web, DB, DNS 서버 등)를 동시에 띄우고 테스트할 수 있습니다.

---

### 1.4 원활한 실습 준비

#### 1.4.1 VMware 단축키 (Hot Key)
* `Ctrl + G` : 호스트(Windows)에서 VM 화면 안으로 마우스/키보드 제어권 넘기기
* `Ctrl + Alt` : VM 안에서 빠져나와 호스트(Windows)로 제어권 돌리기

#### 1.4.2 종료 옵션 (전원 관리)
* **Suspend (일시정지):** 현재 작업 상태를 그대로 메모리에 저장하고 멈춥니다. 빠른 재개에 유용합니다.
* **Power Off (강제 종료):** 실제 컴퓨터의 전원 플러그를 뽑는 것과 같으므로 데이터 유실에 주의해야 합니다.

#### 1.4.3 전체 화면 사용 및 여러 VM 동시 실행 기능 활용
* 실무 환경과 유사한 다중 서버 아키텍처 구성을 위해 여러 VM을 동시에 제어하는 방법을 숙지합니다.

#### 1.4.4 가상 네트워크 종류 파악

| 종류 | 인터넷 연결 여부 | 특징 및 통신 범위 | 
| :--- | :---: | :--- |
| **Bridged** | ⭕ 가능 | 실제 PC와 동일한 네트워크 대역의 IP를 공유기에서 직접 할당받음. PC와 VM이 대등한 독립 장비로 동작. |
| **NAT** | ⭕ 가능 | **[실습 주력]** 호스트 PC 내부 IP를 공유받아 사용. VM에서 인터넷은 가능하나, 외부에서 VM으로의 직접 접근은 차단되어 보안상 유리. |
| **Host-Only** | ❌ 불가 | 외부 인터넷과 단절된 폐쇄망 구축 시 사용. 호스트 PC와 가상머신들 사이에서만 내부 통신 가능. |

#### 1.4.5 파일 전송 방법 (Windows ➔ Linux)
1. Drag & Drop (드래그 앤 드롭)
2. Shared Folder (VMware 공유 폴더 설정)
3. **SCP** (Secure Copy Protocol) 🌟 *실무 다빈도*
4. **WinSCP** (GUI 기반의 FTP/SFTP 클라이언트 프로그램) 🌟 *실무 다빈도*

<summary><h2>2장. 우분투 리눅스 소개</h2></summary>

> **개요:** 리눅스의 탄생 배경과 핵심 구성 요소인 커널(Kernel) 및 셸(Shell)의 개념을 이해하고, 우분투 배포판의 특징과 주요 패키지를 학습합니다.

---

### 2.1 리눅스의 개요

#### 2.1.1 리눅스의 탄생
* **초기 컴퓨터:** 운영체제(OS)가 없어 하드웨어에 프로그램을 직접 입력해야 하는 극심한 불편함이 존재했습니다.
* **UNIX의 등장:** 안정성, 멀티태스킹, 다중 사용자 지원을 무기로 혁명을 일으켰으나, 지나치게 높은 비용이 단점이었습니다.
* **Linux의 탄생:** 리누스 토발즈(Linus Torvalds)라는 대학생이 유닉스를 기반으로 취미 삼아 무료 운영체제 핵심인 **Linux Kernel**을 개발했습니다.
* **성공 요인:** 무료 이용 가능, 소스 코드 완전 공개(Open Source), 전 세계 개발자의 자유로운 수정 및 기여가 가능했기 때문입니다.

#### 2.1.2 GNU 프로젝트
* **개념:** "모든 사람이 자유롭게 사용할 수 있는 소프트웨어 생태계를 만들자"는 이념으로 시작된 프로젝트입니다.
* **성공과 공백:** `bash`, `gcc`, `gdb`, `coreutils` 등 운영체제에 필요한 핵심 도구들을 완벽히 만들었으나, 정작 시스템을 조율할 '커널'이 완성되지 못한 상태였습니다.
* **완성:** GNU의 다양한 오픈소스 도구들과 리누스 토발즈가 만든 **Linux Kernel**이 결합하면서 오늘날 우리가 사용하는 완전한 형태의 리눅스 OS가 완성되었습니다.

#### 2.1.3 커널 (Kernel)
* **정의:** 운영체제의 핵심이자 하드웨어를 직접 제어하고 관리하는 '컴퓨터의 최상위 관리자'입니다.
* **셸(Shell)의 필요성:** 사용자는 커널에게 직접 명령을 내릴 수 없습니다. 따라서 중간에서 사용자의 명령을 커널이 이해할 수 있도록 번역해 주는 **통역사 역할의 Shell**이 반드시 필요합니다.

> **💡 명령어 처리 흐름 예시**
> `사용자` ➔ `Shell (ls 입력)` ➔ `Kernel` ➔ `하드웨어 (디스크 조회)` ➔ `결과 화면 출력`

* **커널의 5대 핵심 역할:**
  1. **CPU 관리:** 어떤 프로그램에 CPU 연산 자원을 우선 배정할지 결정
  2. **메모리 관리:** 각 프로그램에 RAM 공간을 안전하게 할당하고 회수
  3. **파일 관리:** 디스크 저장 장치에 파일을 읽고 쓰는 권한 및 구조 제어
  4. **네트워크 관리:** TCP/IP 프로토콜 스택 처리 및 데이터 송수신 관리
  5. **장치 관리:** USB, SSD, 랜카드(NIC), 프린터 등 물리 장치 드라이버 제어

---

### 2.2 우분투 리눅스 배포판
* **배포판(Distribution)이란?** 리눅스 커널 자체만으로는 일반 사용자가 쓸 수 없기 때문에, `커널 + 명령어 + 패키지 관리자 + 설치 프로그램 + GUI`를 하나로 묶어 구성한 완전한 운영체제 패키지입니다. (ex. Ubuntu, Debian, Rocky Linux, AlmaLinux, Fedora 등)

#### 2.2.1 데비안과 우분투
우분투는 데비안(Debian) 리눅스를 모태로 하여 파생된 배포판입니다.
* **Debian 특징:** 철저한 검증을 거치므로 매우 안정적이고 보수적이지만, 패키지 업데이트가 상대적으로 느립니다.
* **Ubuntu 특징:** 초보자도 접근하기 쉬우며, 최신 패키지를 빠르게 제공하고 전 세계적으로 참고할 수 있는 문서(커뮤니티)가 가장 방대합니다.

#### 2.2.2 우분투 배포판 종류
* **Ubuntu Desktop:** GUI(그래픽 화면)가 기본 포함되어 윈도우처럼 마우스로 조작 가능한 버전입니다.
* **Ubuntu Server:** GUI가 제외된 CLI(텍스트 터미널) 기반으로 작동하며, 서버 자원 낭비를 최소화하여 성능을 극대화한 버전입니다.

#### 2.2.3 우분투 버전 규칙
* **버전 명명:** `YY.MM` 형태로 출시 연도와 월을 나타냅니다. (ex. Ubuntu 24.04는 2024년 4월 출시 제품)
* **LTS (Long Term Support):** 2년마다 출시되는 **장기 지원 버전**으로, 성능이 안정적이고 기술 지원 기간이 길어 기업 실무 환경에서는 대부분 LTS 버전을 채택합니다.

#### 2.2.4 Ubuntu 24.04 설치 요구사항
* **CPU:** 2 Core 이상
* **RAM:** 4GB 이상
* **Disk:** 25GB 이상의 여유 공간

#### 2.2.5 우분투 주요 패키지 요약

| 패키지 명 | 주요 역할 및 특징 |
| :--- | :--- |
| **Bash** | 우분투의 기본 셸(Shell)로 명령어 해석 및 스크립트 실행 담당 |
| **OpenSSH** | 원격지에서 리눅스 서버에 안전하게 암호화 접속하기 위한 필수 보안 프로토콜 |
| **systemd** | 리눅스 부팅 시 시스템 서비스(데몬)들을 전체적으로 제어하고 관리하는 최상위 프로세스 |
| **APT** | 우분투 전용 패키지 관리 도구로, 인터넷을 통해 소프트웨어를 쉽게 설치/삭제 가능 |
| **Vim** | CLI 환경에서 가장 널리 쓰이는 강력한 기본 텍스트 편집기 |
| **Netplan** | 우분투의 최신 네트워크 설정 도구 (`/etc/netplan/` 경로의 YAML 파일로 IP/DNS 관리) |
</details>

<summary><h2>3장. 서버 구축 시 알아야 할 필수 개념과 명령어</h2></summary>

> **개요:** 리눅스 서버 운영의 기본이 되는 전원 관리, 가상 콘솔, 디렉터리 구조, 기본 도구(에디터/마운트) 및 필수 명령어들을 학습합니다.

---

### 3.1 리눅스 운영에서 먼저 알아야 할 개념

#### 3.1.1 시작과 종료
* **시스템 즉시 종료:** `sudo shutdown now`
* **전원 종료:** `sudo poweroff`
* **종료 예약 (10분 뒤):** `sudo shutdown -h +10`
* **예약된 종료 취소:** `sudo shutdown -c`

#### 3.1.2 시스템 재부팅
* **언제 하는가?** 커널 업데이트 적용, 주요 네트워크 설정 변경, 시스템 장애 복구 시 수행합니다.
* **명령어:** `sudo reboot` 또는 `sudo shutdown -r now`

#### 3.1.3 로그아웃 (Logout)
* **개념:** 시스템 자체를 끄지 않고, 현재 로그인된 사용자 세션만 안전하게 종료합니다.
* **명령어:** `exit` 또는 `logout`

#### 3.1.4 가상 콘솔 (Virtual Console)
* 하나의 화면만 사용하는 윈도우와 달리, 리눅스는 하나의 모니터(컴퓨터)에서 여러 개의 독립된 터미널 창을 전환하며 사용할 수 있는 가상 콘솔 기능을 지원합니다.

#### 3.1.5 리눅스 디렉터리 구조 (FHS)
리눅스는 모든 파일과 디렉터리가 최상위 루트(`/`)를 기점으로 역트리(Tree) 구조를 이룹니다.

| 디렉터리 | 주요 역할 및 저장 데이터 |
| :--- | :--- |
| **`/`** | **최상위 루트 디렉터리**, 모든 절대 경로의 시작점 |
| **`/home`** | 일반 사용자들의 개인 홈 디렉터리 공간 |
| **`/root`** | 최상위 관리자(root) 전용 홈 디렉터리 |
| **`/etc`** | 시스템 및 각종 애플리케이션의 **핵심 설정 파일** 저장소 |
| **`/var`** | 시스템 로그, 데이터베이스 파일 등 **동적으로 변하는 데이터** 저장 |
| **`/tmp`** | 시스템 및 프로그램이 사용하는 임시 파일 저장소 |
| **`/usr`** | 일반 사용자들이 실행하는 프로그램 및 유틸리티 저장 설치 경로 |
| **`/bin`** | 시스템의 필수 기본 명령어 모음 (`ls`, `cp`, `mv`, `cat` 등) |
| **`/dev`** | 하드웨어 장치들을 파일 형태로 관리하는 장치 파일 저장소 |
| **`/proc`** | RAM에 상주하는 커널 정보 및 실시간 시스템 정보(가상 파일 시스템) |

#### 3.1.6 런레벨 (Runlevel)
* **개념:** 현재 우분투 등 최신 리눅스에서는 **`systemd` 인프라의 Target 개념으로 대체**되어 사용됩니다.

#### 3.1.7 자동 완성과 히스토리
* **`TAB` 키:** 파일명, 디렉터리명, 명령어 등을 입력할 때 자동으로 완성해 주는 필수 기능입니다.
* **`history`:** 이전에 실행했던 명령어 기록들을 번호 순으로 조회합니다.

#### 3.1.8 에디터 사용
* **`nano`:** 다루기 쉽고 직관적인 텍스트 에디터입니다.
* **`vi` / `vim`:** 리눅스 환경의 실무 표준 에디터입니다.
  * **입력 모드 전환:** `i`
  * **명령 모드 복귀:** `ESC`
  * **저장 후 종료:** `:wq`
  * **저장하지 않고 강제 종료:** `:q!`

#### 3.1.9 도움말 사용법
* **`man [명령어]`:** 특정 명령어의 사용법, 옵션, 매뉴얼 페이지를 상세히 확인합니다.

#### 3.1.10 마운트(Mount)와 스토리지 활용

<summary><h2>4장. 하드디스크 관리와 사용자별 공간 할당</h2></summary>

> **개요:** 리눅스 환경에서 물리 디스크를 추가하고, 파티션 분할, 포맷, 마운트를 통해 실제 저장 공간으로 사용하는 일련의 과정을 학습합니다.

### 4.1 디스크 1개 추가하기
> **전체 작업 프로세스:** 리눅스에서 새로운 스토리지를 확장할 때는 항상 아래의 순서대로 명확히 정형화된 단계를 거쳐야 합니다.
> `디스크 장치 추가` ➔ `파티션(Partition) 생성` ➔ `파일 시스템 생성(포맷)` ➔ `디렉터리 마운트` ➔ `사용 가능`

* **실무 예시:** 운영 중인 리눅스 서버에서 로그 파일 누적, 데이터베이스(DB) 용량 증가, 혹은 유저 업로드 파일 급증으로 디스크 공간이 부족해질 때 새로운 물리/가상 디스크를 장착하고 수동으로 인식시켜 공간을 확장합니다.

---

#### 4.1.1 SATA 장치와 SCSI 장치 구성
리눅스 커널은 저장장치 인터페이스 종류(SATA, SCSI, NVMe 등)에 따라 일관된 디바이스 파일 이름 규칙을 부여하여 관리합니다.

* **인터페이스 종류:**
  * **SATA:** 일반 PC 및 보급형 서버에서 오랫동안 널리 쓰인 규격입니다.
  * **SCSI:** 엔터프라이즈 서버 및 고성능 환경에서 주로 사용하는 안정적인 규격입니다.
* **디스크 장치 이름 식별 규칙:**
  * 첫 번째 디스크 장치: `/dev/sda`
  * 두 번째 디스크 장치: `/dev/sdb`
  * 세 번째 디스크 장치: `/dev/sdc`
* **파티션 분할 이름 식별 규칙:**
  * 하나의 물리 디스크를 논리적으로 분할하면 이름 뒤에 숫자가 붙습니다.
  * (ex) `/dev/sda1`, `/dev/sda2` ➔ `sda` 디스크의 1번 파티션, 2번 파티션을 의미
* **💡 실무 분할 예시:** 100GB 용량의 전체 디스크가 있을 때 이를 통째로 쓰지 않고, 안정적인 관리를 위해 `50GB는 OS 영역`, 나머지 `50GB는 DATA 저장 영역`으로 분리하여 파티셔닝합니다.

##### 🛠️ 디스크 모니터링 관련 핵심 명령어
* **`lsblk`**: 시스템에 연결된 블록 장치(디스크 및 파티션)의 트리 구조와 연결 상태를 트리 형태로 간단히 확인합니다.
* **`sudo fdisk -l`**: 상세 디스크 크기, 실질적인 파티션 테이블 유형, 용량 및 섹터 정보까지 깊이 있게 스캔합니다.

---

#### 4.1.2 디스크 추가 및 인식 실습 6단계

| 단계 | 수행 작업 | 핵심 명령어 | 주요 목적 |
| :--- | :--- | :--- | :--- |
| **1단계** | **파티션 분할** | `fdisk /dev/sdb` | 새로 추가된 `sdb` 디스크 내부에 논리적 구역(Partition) 정의 |
| **2단계** | **파일 시스템 포맷** | `mkfs.ext4 /dev/sdb1` | 생성된 파티션 영역을 리눅스 표준 파일 시스템(`ext4`)으로 포맷 |
| **3단계** | **마운트 포인트 준비** | `mkdir /data` | 디스크 공간을 운영체제와 연결해 줄 타깃 빈 폴더 생성 |
| **4단계** | **디렉터리 마운트** | `mount /dev/sdb1 /data` | 포맷된 디스크 장치 파티션을 새로 만든 `/data` 폴더에 일시적 결합 |
| **5단계** | **fstab 영구 등록** | `vi /etc/fstab` | 서버가 재부팅되어도 자동으로 마운트가 유지되도록 설정 파일에 등록 |
| **6단계** | **최종 용량 검증** | `df -h` | 디스크 용량과 마운트 상태를 사람이 읽기 쉬운 단위(GB/MB)로 최종 확인 |


##### 💡 5단계: /etc/fstab 등록 서식 및 테스트
```text
# [UUID 또는 장치명]    [마운트 포인트]  [파일시스템 타입]  [옵션]    [덤프]  [파일체크순서]
UUID=a1b2c3d4-e5f6...  /data            ext4               defaults  0       2
```
* **⚠️ 재부팅 전 마운트 테스트 필수:** `/etc/fstab` 파일 설정 후 아래 명령어를 실행하여 에러가 발생하지 않는지 반드시 확인해야 부팅 불가 장애를 방지할 수 있습니다.
  ```bash
  sudo mount -a
  ```

<summary><h2>5장. 하드디스크 관리와 사용자별 공간 할당</h2></summary>

> **개요:** RAID를 통한 디스크 신뢰성 확보, LVM을 통한 유연한 볼륨 관리, 그리고 디스크 쿼터를 통한 사용자별 자원 제한 방법을 학습합니다.

---

### 5.2 RAID (Redundant Array of Independent Disks)

#### 5.2.1 RAID의 정의와 개념
* **정의:** 복수의 물리 하드디스크를 하나의 논리적인 대용량 저장 장치로 묶어서 관리하는 기술입니다.
* **핵심 목적:**
  1. **성능 향상 (Performance):** 데이터를 분산 저장하여 읽기/쓰기 속도 증대
  2. **데이터 보호 (Redundancy):** 디스크 장애 시에도 데이터 복구 및 서비스 연속성 보장

#### 5.2.2 핵심 RAID 레벨별 특징 및 비교

| RAID 레벨 | 주요 메커니즘 | 최소 디스크 | 특징 |
| :--- | :--- | :---: | :--- |
| **RAID 0** | 스트라이핑 | 2개 | 성능 극대화, 안전성 없음 |
| **RAID 1** | 미러링 | 2개 | 높은 안전성, 용량 50% 사용 |
| **RAID 5** | 패리티 분산 | 3개 | 성능/안전성 균형 (실무 최다 사용) |
| **RAID 6** | 이중 패리티 | 4개 | 디스크 2개 고장까지 보호 |
| **RAID 10** | 미러링+스트라이핑 | 4개 | 성능과 안전성 모두 최고 |

---

### 5.3 LVM (Logical Volume Manager)

#### 5.3.1 LVM의 개념
* **정의:** 물리적 하드디스크 구조에 종속되지 않고, 여러 디스크를 하나의 큰 풀(Pool)로 묶어 유연하게 용량을 조절하는 기술입니다.
* **LVM 아키텍처:** `물리 디스크(PV)` ➔ `볼륨 그룹(VG)` ➔ `논리 볼륨(LV)`
* **실무 이점:** 
  * **온라인 확장:** 서비스 중단 없이 실시간 용량 증설 가능
  * **유연성:** 파티션 크기를 자유롭게 변경 가능
  * **스냅샷:** 데이터 복구를 위한 시점 보관 기능 지원

#### 5.3.2 LVM 구현 실습 절차
| 단계 | 수행 작업 | 핵심 명령어 |
| :--- | :--- | :--- |
| **1단계** | **PV 생성** | `sudo pvcreate /dev/sdb` |
| **2단계** | **VG 생성** | `sudo vgcreate vgdata /dev/sdb /dev/sdc` |
| **3단계** | **LV 생성** | `sudo lvcreate -L 1G -n lvdata vgdata` |
| **4단계** | **포맷 및 마운트** | `mkfs.ext4`, `mount` |

---

### 5.4 디스크 쿼터 (Quota)

#### 5.4.1 쿼터의 개념
* **정의:** 특정 사용자나 그룹이 사용할 수 있는 디스크 공간 및 파일 개수를 제한하는 기능입니다.
* **필요성:** 사용자 독점 방지, 루트 디렉터리 보호, 효율적인 자원 분배.

#### 5.4.2 제한 방식
* **Soft Limit:** 경고 수준 (유예 기간 내 정리 필요)
* **Hard Limit:** 절대 제한 (초과 시 파일 저장 불가)

#### 5.4.3 설정 실습 절차
| 단계 | 작업 내용 | 실행 명령어 |
| :--- | :--- | :--- |
| **1단계** | **옵션 추가** | `/etc/fstab`에 `usrquota`, `grpquota` 추가 |
| **2단계** | **데이터베이스 생성**| `sudo quotacheck -ugm /data` |
| **3단계** | **기능 활성화** | `sudo quotaon /data` |
| **4단계** | **용량 설정** | `sudo edquota -u [사용자명]` |

### 6.1 셸의 기본

#### 6.1.1 우분투의 bash 셸
* **셸(Shell):** 사용자의 명령을 해석해 커널에 전달하는 통역사.
* **Bash(Bourne Again Shell):** 리눅스 실무 표준 셸. (`echo $SHELL`로 확인 가능)

#### 6.1.2 셸의 명령문 처리
* **특수 문자:**
  * `;`: 순차 실행
  * `&&`: 앞 명령어 성공 시 실행
  * `||`: 앞 명령어 실패 시 실행
  * `|`: 파이프 (결과 전달)

#### 6.1.3 환경 변수
* 시스템 전체에서 참조하는 설정값. (`env`로 확인, `export`로 등록)
* **주요 변수:** `HOME`, `USER`, `HOSTNAME`, `PATH`

---

### 6.2 셸 스크립트 프로그래밍

#### 6.2.1 작성 규칙
* **쉬뱅(Shebang):** 파일 첫 줄에 `#!/bin/bash` 필수 기재.

#### 6.2.2 변수 및 연산
* **대입:** `NAME="kim"` (공백 없음)
* **호출:** `$NAME`
* **입력:** `read 변수명`
* **연산:** `$((A + B))`

#### 6.2.3 if문 (조건 처리)
* **문법:** `if [ $NUM -gt 5 ]; then ... fi` (대괄호 양 끝 공백 필수!)
* **숫자 비교:** `-eq`(같다), `-ne`(다르다), `-gt`(크다), `-lt`(작다), `-ge`(이상), `-le`(이하)

#### 6.2.4 반복문
* **for문:** `for i in {1..5}; do ... done` (지정된 범위 반복)
* **while문:** 조건이 참인 동안 반복.

#### 6.2.5 기타 유용한 개념
* **매개변수:** `$1`, `$2` 등으로 스크립트 실행 시 전달된 인자 사용.
* **함수:** 코드 묶음 처리.
* **종료 코드:** `0`(성공), `0이 아닌 값`(실패).

### 💡 실무 스크립트 예제

      ```bash
            #!/bin/bash

                echo "전달된 매개변수가 없습니다."
            else
                echo "전달된 매개변수 개수: $#"
            fi
            
            # 반복문
            for i in {1..3}
            do
                echo "반복 중... $i"
            done
      ```

> **개요:** 리눅스 서버를 원격에서 관리하기 위한 다양한 프로토콜(Telnet, SSH, XRDP)의 개념과 구축 방법을 학습합니다.

---

### 7.1 텔넷 (Telnet) 서버
* **개요:** 다른 컴퓨터를 원격에서 터미널로 접속하여 명령어를 실행하는 프로토콜입니다.
* **주요 특징:**
    * **포트:** TCP 23번 사용
    * **동작 과정:** Client ➔ `telnet [IP]` ➔ Server ➔ 로그인 ➔ 명령 실행
* **한계점:** 데이터를 암호화하지 않아 보안에 매우 취약하며, 최근에는 거의 사용하지 않고 **SSH**를 대체하여 사용합니다.

---

### 7.2 OpenSSH 서버
* **개요:** 네트워크상의 원격 컴퓨터에 안전하게 로그인하고 명령을 실행할 수 있게 해주는 암호화된 프로토콜입니다.
* **주요 기능:** 원격 로그인, 명령어 실행, 파일 전송, 서버 관리 등
* **보안성:** 통신 내용이 암호화되어 있어 패킷 분석(Wireshark 등)으로도 내용을 알 수 없습니다.
* **인증 방식:** 비밀번호 인증, 공개키 인증 지원
* **포트:** TCP 22번 사용

#### 🛠️ OpenSSH 관리 명령어
* **설치:** `sudo apt update` ➔ `sudo apt install openssh-server`
* **설치 확인:** `dpkg -l | grep openssh`
* **서비스 상태 확인:** `systemctl status ssh` 또는 `systemctl status sshd`
* **포트 확인:** `sudo ss -tnlp` 또는 `sudo lsof -i :22`
* **방화벽 설정:** `sudo ufw allow 22/tcp`

#### ⚙️ 주요 설정
* **설정 파일 경로:** `/etc/ssh/sshd_config`
* **주요 설정 항목:** 
    * `Port`: 접속 포트 변경
    * `PermitRootLogin`: 루트 계정 로그인 허용 여부
    * `PasswordAuthentication`: 비밀번호 인증 사용 여부

---

### 7.3 XRDP 서버
* **개요:** 리눅스 서버를 윈도우 원격 데스크톱과 같이 **원격 바탕화면(GUI)** 형태로 제어할 수 있게 해주는 프로토콜입니다.

<h2>3.1 명령행 인터페이스로 시스템 관리하기</h2>

### 3.1.1 명령행 인터페이스

* **CLI란?**
  * **C**ommand **L**ine **I**nterface
  * 키보드로 명령어를 입력해서 컴퓨터를 사용하는 방식
  * 명령어를 입력해서 시스템을 관리하는 인터페이스

* **CLI와 GUI의 차이**
  * **GUI:** 화면으로 보는 방식
  * **CLI:** 키보드로 명령어를 입력하는 방식

* **CLI를 배워야 하는 이유**
  * 서버에는 GUI가 없는 경우가 많다.
  * 원격 서버를 관리해야 한다.
  * 자동화가 가능하다, CLI는 명령어를 스크립트로 만들 수 있다.
  * 장애 대응에 강하다.

---

### 3.1.2 셸

* **셸이란?**
  * 셸은 사용자가 입력한 명령을 해석해서 운영체제에 전달하는 프로그램이다.

* **터미널과 셸은 다르다.**
  * **터미널:** 사용자가 셸과 상호작용할 수 있게 해주는 창/프로그램이다.
  * **셸:** 명령어를 해석하는 프로그램이다.

* **Bash**
  * Linux에서 가장 많이 접하게 되는 셸이 Bash이다.
  * 셸은 셸 스크립트를 만들 수 있다.

* **셸은 커널이 아니다.**
  * 터미널 = 명령을 입력할 수 있는 환경
  * 셸 = 명령어를 해석하고 실행
  * 커널 = CPU, 메모리, 디스크 등의 시스템 자원 관리
  * 하드웨어 = 실제 CPU, RAM, SSD 등

* **셸 종류**
  * `sh`, `bash`, `zsh`, `fish`, `dash` 등

---
 
<h2>3.2 시작하고 종료하기</h2>

### 3.2.1 셸 시작하기

* **셸 시작과 프롬프트**
  * 리눅스에 로그인하면 명령어를 입력할 수 있는 상태가 된다.
  * **프롬프트(Prompt):** 셸이 사용자의 명령어 입력을 기다리고 있다는 표시

* **일반 사용자와 root 사용자**
  * **일반 사용자:** 프롬프트 끝에 `$` 표시
  * **root 사용자:** 프롬프트 끝에 `#` 표시

* **로그인 셸 (Login Shell)**
  * 리눅스에서는 셸이 시작되는 방식으로 로그인 셸과 비로그인 셸이 존재한다.
  * **로그인 셸:** 사용자가 시스템에 로그인하면서 시작되는 셸이다.
  * `$SHELL`은 일반적으로 사용자 계정에 설정된 로그인 셸을 보여주는 환경변수이다.

* **셸 종료하기**
  * `exit`

---

### 3.2.2 셸 환경 변수

* **환경변수란?**
  * 운영체제와 셸에서 사용하는 환경에 대한 정보를 저장하는 변수

* **대표적인 환경변수**
  * **`HOME`:** 현재 사용자의 홈 디렉터리 (`echo $HOME`)
  * **`USER`:** 현재 사용자 정보 (`echo $USER`)
  * **`SHELL`:** 사용자의 로그인 셸 정보 (`echo $SHELL`)
  * **`HOSTNAME`:** 호스트 이름과 관련된 정보 (`hostname`)
  * **`PATH`:** 가장 중요한 실행 파일 검색 경로 (`echo $PATH`)

* **환경변수 확인**
  * 전체 확인: `printenv` 또는 `env`
  * 특정 변수 확인: `echo $HOME`, `echo $PATH` 등

* **변수를 직접 만들기**
  * `name="a"` 형태로 할당 후 `echo $name`으로 확인

---

### 3.2.3 시스템 종료하기

* **종료 및 재부팅 명령어**
  * `shutdown now`: 즉시 종료
  * `sudo systemctl poweroff` 또는 `sudo poweroff`
  * `sudo reboot` 또는 `sudo systemctl reboot`
  * `sudo shutdown +10`: 10분 후 예약 종료
  * `sudo shutdown -c`: 예약된 종료 취소

## 3.3 사용자 관리하기

### 3.3.1 로그인한 사용자 정보 조회하기
* **현재 사용자 확인하기:** `whoami`
* **로그인한 사용자 확인:** `who`
* **더 자세한 사용자 정보 확인하기:** `w` (실무에서 주로 사용)
* **사용자 ID 확인하기:** `id`
  * **UID:** 리눅스는 내부적으로 숫자로 사용자를 관리한다.

### 3.3.2 루트 권한 획득하기
* **root:** 시스템의 최고 관리자
* **sudo:** 관리자 권한으로 실행
* **root 셸로 전환하기:** `sudo -i` 또는 `sudo su -`

### 3.3.3 사용자 계정 추가하기
* **기본 사용자 생성:** `useradd`
* **홈 디렉터리 생성 포함:** `useradd -m user1` (`-m`은 홈 디렉터리 생성을 의미, `adduser`도 많이 사용됨)
* **사용자 비밀번호 변경:** `passwd`
* **사용자 홈 디렉터리 확인:** `ls /home`
* **사용자만 삭제하기:** `sudo userdel user1`
* **사용자와 홈 디렉터리까지 삭제:** `sudo userdel -r user1`
* **관련 파일 경로:**
  * 사용자 정보: `/etc/passwd`
  * 비밀번호 정보: `/etc/shadow`

### 3.3.4 사용자 계정 전환하기
* **사용자 전환 명령어:** `su user1`
* **로그인 셸 환경까지 포함하여 전환:** `su - user1` (`-`는 사용자의 로그인 환경을 적용한다는 의미)
* **다른 사용자로 전환:** `sudo su - user1` 또는 `sudo -iu user1`
* **원래 사용자로 돌아오기:** `exit`

### 3.3.5 그룹 관리하기
리눅스는 사용자를 하나씩 관리하는 것보다 그룹을 이용해 권한을 관리하는 경우가 많습니다. (그룹은 여러 사용자를 하나로 묶은 것)

* **그룹 생성:** `sudo groupadd developers`
* **그룹 확인:** `getent group developers`
* **전체 그룹 정보 조회:** `cat /etc/group`
* **사용자에게 그룹 추가:** `sudo useradd -aG developers user1` (`-a` 없이 사용하면 기존 보조 그룹이 변경될 수 있음)
* **사용자가 속한 그룹 확인:** `groups user1`
* **그룹에서 사용자 제거:** `sudo gpasswd -d user1 developers`
* **그룹 삭제:** `sudo groupdel developers`
* **기본 개념 및 sudo 그룹:**
  * 사용자는 일반적으로 기본 그룹과 보조 그룹을 가질 수 있습니다.
  * 우분투에서는 관리자 권한을 부여할 때 일반적으로 `sudo` 그룹을 사용합니다.
  * 사용자를 `sudo` 그룹에 추가: `sudo usermod -aG sudo user1`
 
## 3.4 파일 관리하기

### 3.4.1 리눅스에서 파일이란?
* **리눅스에서는 거의 모든 것이 파일이다.**
* **파일의 종류**
  * **일반 파일:** 텍스트, 프로그램, 이미지 등
  * **디렉터리:** 파일을 저장하는 공간
  * **심볼릭 링크:** 다른 파일을 가리키는 링크
  * **블록 장치 파일:** 디스크 관련 장치
  * **문자 장치 파일:** 키보드, 터미널 등
  * **소켓:** 프로세스 간 통신
  * **파이프:** 프로세스 간 데이터 전달
* **권한 문자 기호**
  * `-`: 일반 파일
  * `d`: 디렉터리
  * `l`: 심볼릭 링크

### 3.4.2 파일 목록 화면에 표시하기
* **파일과 디렉터리를 확인하는 가장 기본적인 명령어:** `ls`
* **현재 위치 확인:** `pwd`
* **특정 디렉터리 보기:** `ls /etc`
* **자세한 정보 보기:** `ls -l`
* **숨김 파일 보기:** `ls -a`
* **사람이 읽기 쉬운 파일 크기:** `ls -lh`

### 3.4.3 파일 정보에 대해
* **파일 종류와 권한:** 첫 번째는 일반 파일 유무, 나머지는 권한
* **링크 수:** 파일을 가리키는 링크의 개수
* **소유자:** 파일의 소유자
* **소유 그룹:** 파일이 속한 그룹
* **파일 크기:** 1024 바이트 단위
* **수정 시간:** 마지막으로 수정된 시간
* **파일의 더 자세한 정보를 보고 싶다면:** `stat 파일명`

### 3.4.4 파일 소유권과 접근 권한 변경하기
* **파일 소유권:** 리눅스 파일에는 기본적으로 소유자, 소유 그룹이 있다.
* **파일 권한:** 권한은 세 그룹으로 나뉜다. (소유자, 그룹, 기타 사용자)
* **권한 종류:** `r`(Read), `w`(Write), `x`(Execute)
* **권한 구조:** 소유자 | 그룹 | 기타 (`rwx | r-x | r--`)
* **권한 변경 명령어:** `chmod` (예: `chmod u+x script.sh`)
  * **그룹에 쓰기 권한 추가:** `chmod g+w file.txt`
  * **기타 사용자 권한 제거:** `chmod o-r file.txt`
* **권한의 숫자 표현:** `r = 4`, `w = 2`, `x = 1`
  * `chmod 755`: `7` -> rwx, `5` -> r-x, `5` -> r-x
* **자주 사용하는 권한**
  * `755`: 디렉터리, 실행 파일
  * `644`: 일반 파일
  * `700`: 소유자만 접근
  * `600`: 민감한 개인 파일
* **파일 소유자 변경:** `chown` (예: `sudo chown 사용자 파일명`)
* **사용자와 그룹 동시에 변경:** `sudo chown kim:developers test.txt`
* **파일 그룹 변경:** `chgrp` (예: `sudo chgrp developers test.txt`)

### 3.4.5 리눅스 시스템 디렉터리
* **최상위 디렉터리:** `/`
* **일반 사용자의 홈 디렉터리:** `/home`
* **root 사용자의 홈 디렉터리:** `/root`
* **시스템 설정 파일:** `/etc`
* **변하는 데이터:** `/var`
* **시스템 로그가 저장되는 곳:** `/var/log`
* **기본 명령어:** `/bin`
* **부팅 관련 파일:** `/boot`
* **장치 파일:** `/dev`
* **임시 파일:** `/tmp`
* **프로그램과 라이브러리 등 많은 사용자 공간 데이터 포함:** `/usr`

### 3.4.6 디렉터리 다루기
* **현재 위치 확인:** `pwd`
* **디렉터리 이동:** `cd`
* **특정 디렉터리 이동:** `cd /etc`
* **상위 디렉터리:** `cd ..`
* **홈 디렉터리:** `cd ~`
* **이전 디렉터리:** `cd -`
* **디렉터리 생성:** `mkdir 디렉터리명`
* **여러 단계 생성:** `mkdir -p project/src/tmp`
* **디렉터리 삭제:** `rmdir 디렉터리명`
* **내용이 있는 디렉터리 삭제:** `rm -rf 디렉터리명`

### 3.4.7 파일 다루기
* **파일 생성:** `touch 파일명`
* **여러 파일 생성:** `touch file1.txt file2.txt file3.txt`
* **파일 복사:** `cp 원본 대상`
* **디렉터리 복사:** `cp -r project backup_project`
* **파일 이동:** `mv 파일 대상`
* **파일 이름 변경:** `mv old.txt new.txt`
* **파일 삭제:** `rm 파일명`

### 3.4.8 파일 내용 확인하기
* **`cat 파일명`:** 짧은 파일을 확인할 때 좋다.
* **`less 파일명`:** 긴 파일을 볼 때 좋다.
* **`head 파일명`:** 파일의 앞부분을 확인한다.
* **`tail 파일명`:** 파일의 마지막 부분을 확인한다.
* **`tail -f 로그파일`:** 로그가 실시간으로 추가되는 것을 확인한다.
* **`grep`:** 원하는 내용을 검색한다 (예: `grep "error" 파일명`)
  * **대소문자 무시:** `grep -i error 파일명`
  * **여러 명령어와 함께 사용:** `cat 파일명 | grep error`

### 3.4.9 파일 검색하기
* **실시간 파일 시스템 검색:** `find 검색위치 조건` (예: `find /home -name test.txt`)
  * **확장자 검색:** `find /home -name "*.log"`
  * **디렉터리 검색:** `find /home -type d -name project`
  * **파일 검색:** `find /home -type f -name "*.txt"`
* **파일 데이터베이스를 이용한 빠른 검색:** `locate 파일명`
* **명령어의 실행 파일 위치 찾기:** `which ls`
* **명령어와 관련된 파일 찾기:** `whereis ls`


## 3.5 프로세스 관리하기 

 ### 3.5.1 프로세스란 무엇인가? 실행 중인 프로그램
    * 프로그램과 프로세스 차이 : 프로그램(디스크에 저장된 실행 파일), 프로세스(메모리에서 실행 중인 프로그램)
    * 프로세스가 실행되면? : 프로그램을 실행하면 운영체제가 프로세스를 생성한다. 각 프로세스는 고유한 번호(PID)를 부여받는다.
    * PID 확인 : 프로세스를 확인할 때 가장 많이 사용하는 명령어 : `ps`
    * 부모 프로세스와 자식 프로세스 : 리눅스 프로세스는 보통 계층 구조를 가진다.
    * PPID : 부모 프로세스의 PID를 PPID라고 부른다.
    * PID 1은 매우 중요하다 : 리눅스 시스템이 부팅되면 가장 먼저 중요한 사용자 공간 프로세스(systemd)가 실행된다.

  ### 3.5.2 프로세스 확인하기**
    * 프로세스를 확인하는 대표적인 명령어는 : `ps`
    * `ps` : 현재 터미널에서 실행 중인 프로세스를 확인한다.
    * `ps -ef` : UID(실행 사용자), PID(프로세스 ID), PPID(부모 프로세스 ID), CMD(실행 명령어)
    * 특정 프로세스 찾기 : `ps -ef | grep nginx` 또는 `pgrep nginx`
    * `ps aux` : USER(프로세스 실행 사용자), PID(프로세스 ID), %CPU(CPU 사용률), %MEM(메모리 사용률), COMMAND(실행 명령)
    * CPU 많이 사용하는 프로세스 찾기 : `ps aux --sort=%cpu`
    * 메모리 많이 사용하는 프로세스 찾기 : `ps aux --sort=%mem`
    * `top` : 실시간 프로세스를 확인한다. (CPU 사용량, 메모리 사용량, 프로세스 상태, PID, 실행 사용자)
    * `htop` : `top`보다 보기 편한 도구

  ### 3.5.3 열린 파일 목록 조회하기**
    * 리눅스에서는 모든 것은 파일처럼 관리된다.
    * `lsof` : 열려 있는 파일을 확인한다. (List Open Files)
    * 특정 파일을 사용하는 프로세스 확인 : `lsof /var/log/syslog`
    * 특정 PID의 열린 파일 확인 : `lsof -p PID`
    * 포트를 사용하는 프로세스 확인 : `sudo lsof -i :80`

  ### 3.5.4 작업 제어하기**
    * 터미널에서 실행하는 작업(job)을 관리하는 방법이다.
    * 포그라운드(Foreground) : 일반적으로 명령어를 실행하면 포그라운드에서 실행된다. (명령어가 실행되는 동안 터미널을 사용할 수 없다.)
    * 백그라운드(Background) : 명령어 뒤에 `&`를 붙이면 백그라운드에서 실행된다.
    * `jobs` : 현재 셸의 백그라운드 작업을 확인한다.
    * `Ctrl + Z` : 실행 중인 작업을 일시 정지한다.
    * `bg` : 정지된 작업을 백그라운드에서 실행한다.
    * `fg` : 백그라운드 작업을 다시 포그라운드로 가져온다. (특정 작업: `fg %1`)

  ### 3.5.5 프로세스 상태 변경하기**
    * `kill` : `kill`은 무조건 프로세스를 죽이는 명령어가 아니고 시그널을 보내는 명령어이다.
    * 강제 종료 : `kill -9 PID` (프로세스를 즉시 종료한다.)
    * 프로세스 이름으로 종료하기 : `pkill nginx`
    * `killall nginx` : 이름이 같은 프로세스를 종료한다.
    * 프로세스 상태(State) : 프로세스에는 여러 상태가 있다. (R: 실행 중 또는 실행 대기, S: 인터럽트 가능한 대기, D: 인터럽트하기 어려운 I/O 대기, T: 정지 상태, Z: Zombie 상태)           


## 3.6 패키지 관리하기

### 3.6.1 패키지 관리란 무엇인가?
* **패키지 관리란?** Ubuntu에서는 대부분 프로그램을 패키지(Package) 형태로 관리한다.
* 패키지 관리로 할 수 있는 작업 : 설치, 삭제, 업데이트, 업그레이드, 버전 확인, 설치 파일 확인, 의존성 관리
* `dpkg` : 개별 `.deb` 파일을 관리하는 기본 도구
* `apt` : 저장소까지 연결해서 편리하게 패키지를 관리하는 도구
* **dpkg란?** Debian Package의 약자로 Ubuntu는 Debian 계열이기 때문에 `.deb` 형식의 패키지를 사용한다.
* `.deb 파일이란?` 윈도우의 `.exe` 같은 파일이라고 생각하면 된다.
* dpkg로 패키지 설치하기 : `sudo dpkg -i 패키지파일.deb` (예: `sudo dpkg -i program.deb` / 여기서 `i`는 install)
* dpkg의 중요한 단점 : dpkg는 의존성을 자동으로 해결하는 데 한계가 있다.
* 설치된 패키지 확인하기 : `dpkg -l` 또는 `dpkg --list`
* 특정 패키지 찾기 : `dpkg -l | grep nginx`
* 패키지 정보 확인하기 : `dpkg -s 패키지명` (예: `dpkg -s nginx`)
* 패키지가 설치한 파일 확인하기 : `dpkg -L 패키지명` (예: `dpkg -L nginx`)
* 특정 파일이 어느 패키지에 속하는지 확인 : `dpkg -S /usr/bin/ls` (`-S` = Search)
* 패키지 삭제하기 : `sudo dpkg -r 패키지명`
* 완전 삭제 : `sudo dpkg -P 패키지명` (패키지 삭제 + 설정 파일 삭제)

### 3.6.2 향상된 패키지 관리 도구 apt
* **apt란?** Advanced Package Tool, dpkg보다 편리하게 패키지를 관리할 수 있다.
* Repository : 패키지를 저장해 놓은 서버이다.
* `sudo apt update` : 패키지 저장소의 최신 패키지 목록 정보를 가져오는 작업이다. (이것만으로 설치된 것이 최신 버전으로 바뀌진 않는다.)
* `sudo apt upgrade` : 설치된 패키지를 업그레이드한다.
* 패키지 설치 : `sudo apt install 패키지명` (예: `sudo apt install nginx`)
* 여러 개 설치 : `sudo apt install nginx mysql-server curl` 처럼 한 번에 여러 패키지를 설치할 수도 있다.
* 패키지 삭제 : `sudo apt remove nginx` (패키지를 삭제하지만 설정 파일은 남을 수 있다.)
* 완전 삭제 : `sudo apt purge nginx`
* 더 이상 필요 없는 패키지 삭제 : `sudo apt autoremove`
* 패키지 검색 : `apt search 키워드` (예: `apt search nginx` / 설치 가능한 패키지를 검색한다.)
* 패키지 정보 확인 : `apt show 패키지명`
* 설치된 패키지 목록 : `apt list --installed`
* 특정 패키지 찾으려면 : `apt list --installed | grep nginx`
* 설치 가능한 버전 확인 : `apt policy nginx`

## 3.7 서비스 관리하기
systemd는 서비스 시작, 중지, 재시작, 상태 확인, 부팅 시 자동 시작 설정, 로그 확인 관리를 담당한다.

### 3.7.1 시스템 관리자 systemd
* **systemd란?** 리눅스 시스템과 서비스를 관리하는 시스템 관리자(초기화 시스템)이다. (리눅스 서버의 서비스 관리자라고 생각하면 된다.)
* **systemd는 언제 실행될까?** 커널이 실행된 이후 systemd가 시스템을 관리하기 시작한다.
* systemd가 하는 일 : 시스템 부팅 관리(서버가 부팅될 때 필요한 서비스를 실행한다), 서비스 관리(서비스를 시작하거나 중지), 서비스 상태 확인, 부팅 시 자동 실행 설정, 로그 관리
* systemd와 systemctl의 관계 : `systemd`(실제로 시스템을 관리하는 프로그램), `systemctl`(관리자가 systemd를 조작하기 위해 사용하는 명령어)

### 3.7.2 systemctl로 시스템 상태 조회하기
* 서비스 상태 확인 : `systemctl status 서비스이름` (`Loaded`: 서비스가 systemd에 등록되어 있는지 확인, `Active`: 서비스가 현재 실행 중인지 보여준다)
* 시스템 전체 상태 확인 : `systemctl status` 또는 systemd 자체의 상태 확인 (`systemctl is-system-running`)
* 실패한 서비스 확인 : `systemctl --failed`
* 장애 상황 예시 : 시스템 이상 발견 $\rightarrow$ `systemctl --failed` $\rightarrow$ 문제 서비스 확인 $\rightarrow$ `systemctl status 서비스 이름` $\rightarrow$ `journalctl -u 서비스 이름`

### 3.7.3 systemctl로 서비스 제어하기
* 서비스 시작 : `sudo systemctl start apache2`
* 서비스 중지 : `sudo systemctl stop apache2`
* 서비스 재시작 : `sudo systemctl restart apache2`
* 설정 다시 읽기 : `sudo systemctl reload apache2`
* `restart`와 `reload` 차이 : `restart`는 서비스를 다시 시작하고, `reload`는 설정만 다시 읽음
* 서비스 활성화 여부 확인 : `systemctl is-active apache2`
* 부팅 시 자동 시작 설정 : `sudo systemctl enable apache2`
* 자동 시작 해제 : `sudo systemctl disable apache2`

### 3.7.4 journalctl로 systemd 로그 정보 조회하기
* **journalctl이란?** systemd의 로그를 확인하는 명령어이다.
* 전체 로그 보기 : `journalctl` (시스템의 journal 로그를 확인합니다.)
* 특정 서비스 로그 확인 : `journalctl -u ssh`
* 최근 로그 확인 : `journalctl -n 50`
* 실시간 로그 보기 : `journalctl -f`, `journalctl -u apache2 -f` (특정 서비스 실시간 로그)
* 오늘 발생한 로그 확인 : `journalctl --since today`
* 특정 시간 로그 확인 : `journalctl --since "2026-09-10 09:00:00"`
* 특정 시간 이후 로그 : `journalctl --since "1 hour ago"`
* 실제 서버 운영 흐름 : 고객 문의 발생 $\rightarrow$ 서버 접속 $\rightarrow$ `systemctl status apache2` $\rightarrow$ `systemctl --failed` $\rightarrow$ `journalctl -u apache2` $\rightarrow$ `journalctl -u apache2 --since today` $\rightarrow$ `journalctl -u apache2 -f`
      
## 3.8 vi 편집기 익히기

### 3.8.1 vim으로 업데이트하기
* **vi와 vim은 무엇인가?** 리눅스에서 텍스트 파일을 편집할 때 사용하는 대표적인 편집기가 vi이다.
* vi 특징 : vi는 여러 가지 모드를 가지고 있다.
* **vi와 vim의 차이** : vim은 Vi Improved로, vi의 기능을 확장한 편집기이다.
* vim 설치 : `sudo apt update`, `sudo apt install vim`, `vim --version` (버전 확인)
* vi 또는 vim 실행 : 파일이 있다면 해당 파일을 열고, 없다면 새로 생성할 수 있다.

### 3.8.2 vi 모드
* **명령 모드** : `dd`(현재 줄 삭제), `yy`(현재 줄 복사), `j`(아래로 이동), `k`(위로 이동)
* `ESC` : 보통 명령 모드로 돌아오는 역할을 한다.
* 입력 모드 : `i` (입력 모드 종료는 `ESC`)
* 입력 모드로 들어가는 대표적인 방법 : 
  * `i` : 현재 커서 위치에서 입력
  * `a` : 현재 커서 다음 위치에서 입력
  * `o` : 현재 줄 아래에 새로운 줄을 만들고 입력
  * `O` : 현재 줄 위에 새로운 줄을 만들고 입력
* **ex 모드** : 명령 모드에서 `:`를 입력하면 화면 아래쪽에 명령어를 입력할 수 있다. (`:w`(저장), `:q`(종료), `:wq`(저장 후 종료))

### 3.8.3 명령 모드에서 사용할 수 있는 키
* 커서 이동 : 방향키 또는 `h`(왼쪽), `j`(아래), `k`(위), `l`(오른쪽)
* 단어 이동 : `w`(다음 단어로 이동), `b`(이전 단어로 이동)
* 줄 이동 : `0`(현재 줄의 처음으로 이동), `$`(현재 줄의 끝으로 이동)
* 파일 처음과 끝 : `gg`(파일 처음), `G`(파일 끝)
* 특정 줄로 이동 : `100G` (100번째 줄로 이동)
* 삭제 : 현재 글자 삭제(`x`), 현재 줄 삭제(`dd`), 여러 줄 삭제(`5dd` - 현재 위치부터 5줄 삭제)
* 복사 : `yy`(현재 줄 복사), `5yy`(5줄 복사)
* 붙여넣기 : `p` (커서 아래쪽 또는 뒤에 붙여 넣는다.)
* 실행 취소 : `u`
* 다시 실행 : `Ctrl + r`
* 검색 : 명령 모드에서 `/nginx`, `n`(다음 검색 결과), `N`(이전 검색 결과)

### 3.8.4 파일 작성하기
* 파일 열기 또는 생성 : `vi test.txt`
* 입력 모드 진입 : `i`
* 내용 입력
* 명령 모드로 돌아가기 : `ESC`
* 저장 : `:w`
* 종료 : `:q`

### 3.8.5 ex 모드에서 사용할 수 있는 명령
* 저장 : `:w`
* 종료 : `:q` (저장하지 않고 종료하면 거부될 수 있다.)
* 강제 종료 : `:q!`
* 저장 후 종료 : `:wq`
* 강제 저장 : `:w!`
